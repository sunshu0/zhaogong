## 1. 产品是什么

面向海外华人的中文招聘平台，「海外版的 BOSS 直聘」。第一站奥克兰，先做餐饮、零售这类服务工作，再复制到澳洲。核心三件事：

1. 用 AI 帮老板一分钟写好规范的中英双语招聘帖；
2. 验证雇主是真实公司；
3. 不让低于最低工资、收押金、卖工签、按种族招人的帖子发出来。

对外一律说「中文招聘」，不说「华人招聘」：新西兰《人权法》第 67 条禁止按种族招人，语言要求可以写。

**不向求职者收费。** 先免费把职位做多；奥克兰活跃职位到 300 个以上，再对雇主收置顶、急招等增值费（项目说明，非本阶段功能）。

## 2. 用户

| 用户 | 典型场景 |
| --- | --- |
| 求职者 | 在奥克兰的留学生、打工度假、工签和新移民，从微信群或小红书的链接进来，用手机看工作 |
| 雇主 | 华人餐馆、超市、美容、清洁、建筑等小店老板，平时在微信群和天维发招聘 |
| 平台审核 | 处理被规则拦下或被举报的职位，封禁违规雇主 |

一个账号可以同时是求职者和一家企业的雇主，随时切换（R-03）。

## 3. 必守规则（所有需求都受约束）

- **N-1 合规：** 时薪不得低于当地最低工资（新西兰 2026-04-01 起 23.95 纽币）；不得收取押金、介绍费、培训费等任何费用；不得卖签证或暗示包办签证；不得按种族或国籍招人。
- **N-2 不给签证建议：** 签证字段只陈述「雇主接受哪些签证」，并注明不构成签证或移民建议。
- **N-3 不收集敏感身份：** 不设种族、民族、国籍字段；只允许语言要求。
- **N-4 联系方式保护：** 联系方式只给登录用户看，且按 R-12 的两套规则。
- **N-5 真实：** 不编造数字和评价；首页统计都是真实计数，演示数据期间标「演示数据」，正式上线后低于门槛的统计不显示。
- **N-6 手机优先：** 先按 375 px 手机设计，第一版是手机网页，微信里能打开和转发，不用下载 App。

## 4. 需求项

### 账号与身份

**R-01 注册和登录**
- 用户：求职者、雇主。场景：从职位或发帖入口被要求登录。
- 验收：邮箱 + 6 位验证码，注册和登录是同一步（「注册或登录」）；登录后回到原来的页面（只允许站内地址）；可选「我要找工作 / 我要招人」。
- 状态：已做（#28，关闭 #9；ADR 0007）：真实验证码（散列存储、10 分钟过期、每分钟一次、错 5 次作废）、httpOnly cookie 的服务器会话。开发环境在页面上显示验证码；生产环境要接上邮件服务才能发，接哪家由用户决定（**计划中**，#16）。

**R-02 开通雇主身份**
- 用户：雇主。场景：第一次发布招聘。
- 验收：登录后选择一家演示店或新建企业（店名、地区）；一家企业只能绑定一个账号，已被绑定的演示店显示「已被绑定」且不可选，默认选中可用的一项；发布前必须先有雇主身份。
- 状态：已做。

**R-03 一个账号两种身份**
- 用户：既找工作又招人的人。
- 验收：账号菜单和「我的」里切换求职者 / 雇主；两种身份的聊天、主页、通知、记录互不可见；写操作在服务器上按账号核对企业，不信任浏览器。
- 状态：已做（ADR 0003）。

### 求职者

**R-04 浏览职位不需登录**
- 场景：从微信或小红书点链接进来。
- 验收：`/jobs` 不登录可看；首页 `/` 是介绍页（定位、真实统计、功能展示、精选工作、雇主入口）。真实统计是首屏的一句话：在招职位、已验证雇主，以及达到门槛的找到工作人数和咨询次数（#51）。
- 状态：已做。

**R-05 筛选和搜索**
- 验收：按地区、行业、用工形式（全职 / 兼职 / 临时工，可多选）、最低时薪、雇主接受的签证、包餐、包住筛选；中英文关键词搜索；条件写在网址里，可分享；筛选收在一个「筛选 · N」按钮里，已选条件显示为可删除的标签。
- 状态：已做。

**R-06 紧凑职位卡**
- 验收：卡片只放职位名（中英）、薪资（最醒目）、企业名和验证标识、地区、用工形式、工时，最多 3 个标签（急招、包餐、包住、接受学签）；手机一屏至少 3 张卡；整卡可点但只有标题是链接。
- 状态：已做（A21）。

**R-07 职位详情**
- 验收：中英文标题和描述；薪资和最低工资对比；关键信息在标题下的信息格里（薪资、地区、工时和班次、用工形式、食宿、接受的签证）；雇主验证标识和一句解释；发布日期和到期天数；分享（系统分享、复制链接、复制文案，文案不含联系方式）；分享到微信时标题、时薪、地区在页面元数据里。
- 状态：已做（A3、A29）。

**R-08 举报职位**
- 验收：选择原因（虚假职位、收押金或介绍费、低于最低工资、歧视、卖工签、不当内容、其他）加补充说明；不登录也能举报；同一设备举报过会提示；举报进入审核后台。
- 状态：已做；举报记录存在数据库（#31，关闭 #11）。

**R-09 我的主页（求职者）**
- 验收：顶部显示「雇主看到的样子」；资料完成度（如 6/10），标出雇主最看重的五项：可上班时间、地区、期望时薪、语言、经验；必填和选填分开，选填默认收起；可选择是否允许向雇主推荐；改动自动保存并如实显示保存结果。
- 状态：已做（C4、C5）。

**R-10 浏览与举报记录**
- 验收：`/me` 列出看过的职位和发出的举报；可清除浏览记录。
- 状态：已做（记录在浏览器）。

### 雇主

**R-11 AI 发帖**
- 场景：老板粘贴平时发微信群的那段话，或一句一句说。
- 验收：默认对话模式，AI 一次问一个缺的或有疑问的问题（职位名、时薪、工时、地区、用工形式、签证、食宿、联系方式），能选的给快捷选项，旁边实时显示职位卡；也可以「直接填表」；生成中英双语职位，所有字段可改；进度显示「已填 N / 共 M 项」，点哪项跳到哪项。不登录也能开始写，发布前需要雇主身份。
- 状态：已做（规则版，接口按以后接模型设计；B16、B27）。接真实 AI 模型为**计划中**，等用户决定服务商。

**R-12 两套联系方式**
- 验收：发帖和编辑时选择「公开给登录的求职者」（至少填电话、微信、邮箱之一）或「不公开，求职者在聊天中申请交换」（默认）。公开时登录求职者直接查看并计入查看统计；不公开时只能在聊天中交换，发起方先提供自己的资料，对方同意后才给回；没有「交换地址」。
- 状态：已做（B20、B23、A24、A25）。ADR 0002。

**R-13 发布前合规检查**
- 验收：低于最低工资、收费用词（押金、介绍费、培训费、服装费、手续费、报名费、bond 等）、卖签证用词（包签、包工签、包身份、办身份、包 PR、保移民、帮办签证等）**直接拦下**；按种族或国籍招人（限华人、仅招华人、华裔优先、国人优先等）**必须改写才能发布**，提示改成语言要求（如「需会普通话」）；按摩、陪酒、KTV 等进入人工审核；否定写法只认紧贴形式（如「免押金」），对签证类和种族类不生效（「包签 无需经验」照样拦下）；插空格和符号也能识别。非认证雇主不能勾选「持 AEWV 工签者」。
- 状态：已做（B1、B21、B22 第一部分）。

**R-14 复制到其他平台**
- 验收：发布后一键复制微信群、小红书、天维三种文案，都带职位链接、不带联系方式（按 R-12 写清怎么联系）。
- 状态：已做。

**R-15 职位管理**
- 验收：`/employer/jobs` 是职位管理的唯一入口；职位 30 天到期，可刷新、编辑、结束招聘（可选填写招到几个人，之后可更正）、重新开放、复制文案；每张卡一个主按钮「查看」，其余收进「更多」；卡上显示聊天人数和「N 人查看了联系方式」或「聊天交换」。
- 状态：已做（B6、B14、B26）。

**R-16 企业验证**
- 验收：按公司名或 NZBN 查新西兰企业登记，认领后显示「已验证企业」；三级标识（认证雇主、已验证企业、未验证）一眼能分开，各有一句解释，不暗示能办签证。
- 状态：已做（演示登记表）；接真实 NZBN 接口为**计划中**。

**R-17 推荐人才**
- 验收：按选中的职位推荐公开了主页的求职者；每张卡统一五项（可上班时间、地区、期望时薪、语言、经验）；「需关注」只列最关键的两项；匹配分低于 40 的折叠到底部「另外 N 位匹配度较低」；可直接发起聊天。
- 状态：已做（B28）。

**R-18 求职者主页（雇主看到的）**
- 验收：从聊天或推荐人才进来时顶部显示是哪个职位（职位名、时薪），给出「回到聊天」或「发起聊天」；五项条件放最前面，名称和顺序同 R-17。
- 状态：已做（C6）。

**R-19 企业主页**
- 验收：公开页显示企业介绍、招聘联系人、在招岗位、公司资质；雇主在 `/profile` 编辑，顶部预览求职者看到的样子，完成度标出求职者最看重的企业介绍、地区、企业验证、招聘联系人。
- 状态：已做（C4）。

### 双方共用

**R-20 聊天**
- 验收：求职者在职位详情点「立即沟通」开始聊天；对话上方固定显示在聊哪个职位；交换资料和联系方式收进输入框旁的「＋」；对方消息命中收费、签证、种族规则时在消息下提醒并给举报入口，自己发送前命中时提示修改但不拦截；可以举报聊天（附证据）。
- 状态：已做（A24、A26、A30）；按身份存在服务器的数据库里、浏览器只做缓存（#29 关闭 #10；#45 存进数据库，关闭 #42）。

**R-21 通知**
- 验收：交换请求、职位动态等通知，未读数，点开去对应的聊天或页面。
- 状态：已做；已读状态按身份存在服务器（#29）。

**R-22 导航**
- 验收：手机底部导航按身份（未登录：职位 · 聊天 · 我的；求职者：职位 · 聊天 · 我的；雇主：职位管理 · 发布 · 聊天 · 我的），聊天显示未读数；每个功能只有一个入口、一个名字（见 `docs/design-system.md`）；「我的」集中头像、身份切换、通知、主页、记录和退出登录。
- 状态：已做（C2）。

**R-23 工作台「待办」**
- 验收：`/workspace` 只列要处理的事，按急迫程度：等你同意的交换请求、未读聊天、（雇主）7 天内到期和审核中的职位、资料还差几项；没有时一句话加一个主按钮。
- 状态：已做（C3）。

### 平台

**R-24 审核后台**
- 验收：规则拦下的待审职位和被举报的职位（只收职位举报）；通过、下架、驳回举报、封禁雇主，每个操作记日志；线上默认关闭，只有设置 `ADMIN_ENABLED=1` 才开放。
- 状态：已做。只有审核员能用（#50，ADR 0007 补充）：第一位审核员用 `npm run admin:grant` 添加，之后在 /admin 里增删，最后一位不能移除。

**R-25 数据持久化**
- 验收：职位、企业、账号、举报、审核日志、查看记录存数据库，带版本化迁移和种子数据；`data.ts` 的函数签名不变。
- 状态：已做（#31，Closes #8、#11；ADR 0005）；线上用哪个数据库待用户决定（#15，ADR 0006）。

**R-26 可安装网页**
- 验收：可以「添加到主屏幕」，打开直接进职位列表。
- 状态：已做；iPhone 真机未验证。

**R-27 无障碍**
- 验收：浏览器测试里 axe（WCAG 2.1 AA）无违规；触摸目标至少 44 px；减少动态效果时不播放动画。
- 状态：已做，作为每次推送的门槛。

### 第 14 轮新功能（用户 2026-10-16 选定）

**R-28 收藏职位和求职进度**
- 验收：职位卡和职位详情可以收藏，收藏按账号存在服务器；未登录时先去登录，回来后完成收藏。「我的」里的「收藏和进度」可以给每个职位标进度：已收藏 → 已联系 → 已面试 → 已录用 / 没成；在聊天里交换过联系方式的职位自动标为「已联系」，用户可以改。职位下架或过期后收藏里照样能看到，标明「已下架」。进度只有本人看得到。
- 状态：已做（#52）。

**R-29 职位订阅提醒**
- 验收：在职位列表把当前筛选条件（地区、行业、用工形式、签证、关键词）保存为提醒，每个账号最多 5 个，存服务器。新职位发布并通过合规检查后，匹配的账号在站内「通知」里收到一条，同一个职位对同一个人只提醒一次。「我的」里可以查看、改名、暂停、删除提醒。邮件提醒等邮件服务定了再做（#16）。
- 状态：已做（#72）。职位列表的「保存为提醒」存的是列表的筛选条件（查询串，`job_alerts` 表，迁移 0006），名称默认取条件，可以改。职位直接发布或审核通过时在服务器上匹配，命中记在 `job_alert_hits`（账号 + 职位为主键，所以同一个职位只提醒一次；不提醒发布这个职位的企业自己的账号；暂停的提醒不匹配）。通知只出现在求职者身份里，点开到职位页。邮件提醒还没做，等 #16。

**R-30 导出数据和删除账号**
- 验收：依据新西兰《2020 年隐私法》的查阅和更正原则。「我的 → 账号」里可以下载 JSON 格式的全部个人数据（账号、两种身份的资料、发布的职位、聊天记录、通知已读、举报、收藏和提醒）。删除账号要输入邮箱二次确认：删除账号、会话、验证码、聊天记录、收藏和提醒，雇主的职位全部下架，审核记录和举报只保留不含个人信息的部分并写明理由；删除后立刻退出登录，同一邮箱可以重新注册。最后一个审核员不能删除自己的账号。
- 状态：已做（#54，ADR 0009）。「我的 → 数据与账号」（`/account/data`）：下载 JSON（服务器上的数据加这台设备上的资料、举报和浏览记录）；输入邮箱确认后删除。收藏和求职进度（#52）、职位提醒和提醒过的职位（#53）一起导出和删除。

**R-31 雇主的职位数据**
- 验收：服务器记录每个职位的浏览次数（同一浏览器同一天只算一次，不存 IP）、发起聊天人数、查看联系方式次数。职位管理每条显示这三个数字，职位管理详情显示最近 14 天按天的数字。只有该企业的账号能看到。
- 状态：已做（#55）。职位管理每条显示「N 次浏览 · N 人聊过 · N 次查看联系方式」（不公开联系方式的显示「不公开 · 聊天交换」），点「近 14 天」看按天的表格（`/employer/jobs/[id]/stats`）。浏览用浏览器随机编号的哈希去重；「发起聊天」是求职者第一次就这个职位发消息；迁移 `0005_job_stats`。

**R-32 搜索引擎收录和过期下架**
- 验收：职位详情页带 schema.org `JobPosting` 结构化数据（职位名、描述、发布和截止日期、雇主、地点、时薪、用工形式，不含联系方式）；有 `sitemap.xml`（在招职位、企业主页）和 `robots.txt`（不收录审核后台和个人页面）。职位到截止日期自动按下架处理：列表和 sitemap 不再出现，详情页显示「已截止」。
- 状态：已做（Closes #57；ADR 0008）。

### 第 15 轮新功能（用户 2026-10-16 选定）

**R-33 职位快到期提醒、续期和重新发布**
- 验收：截止前 3 天起，雇主工作台的「待办」和站内「通知」里出现「这个职位 N 天后截止」，同一职位只提醒一次（读取时判断，和 ADR 0008 一致，不加定时任务）。截止前或截止后 14 天内可以「续期」：截止日顺延 14、30 或 60 天（默认 30），续期次数和时间记下来。截止很久的职位「重新发布」：用原内容新建一条，重新走合规检查（最低工资按当时的标准）再发布，原职位保持已截止。职位管理显示「将截止」「已截止」状态，可以按状态筛。被封禁的企业不能续期。
- 状态：已做（#69）。职位管理每个职位只在一个状态下：招聘中、将截止（最后 3 天）、审核中、已截止（到期）、已结束（雇主结束）、已下架，标签页按这六种筛，提醒链接打开「将截止」。续期从原截止日往后推（已截止的从今天算），职位在列表里的位置不变，截止日最远到 90 天后；续期前按现在的规则再检查，已截止的重新上线或进审核。每次续期记在 `job_renewals`（迁移 0009，包括续期前后的截止日），职位管理显示「已续期 N 次」，导出数据里有。截止超过 14 天的职位不能续期，改为「重新发布」（`/employer/jobs/[id]/republish`）：原内容填进发布表单，和发布新职位一样检查后发布成新职位。提醒在截止前 3 天到截止后 14 天之间出现，每个职位每个截止日一条（续期后新的截止日会再提醒）；雇主自己结束的职位不提醒。「刷新」只用于在招的职位（排到前面，至少再开 30 天，不会缩短续期后的截止日），不再用来重新开放已截止的职位。

**R-34 审核数据**
- 验收：审核后台顶部显示现在待审核的职位数、未处理的举报数，以及最早的一条等了多久。「审核数据」一页列出最近 8 周每周的新举报数、处理完的举报数、举报从提交到处理的中位用时、下架职位数、封禁企业数，用表格，不加图表库。统计在服务器上算，只有审核员能看。还列出 8 周里每位审核员的通过、下架、驳回、封禁次数（审核记录写明操作人，#60）。
- 状态：已做（#74；ADR 0010）。举报关闭时记下处理时间（迁移 0008 的 `reports.handled_at`）；之前已处理的举报没有这个时间，不计入用时，页面上写明条数。

### 第 16 轮新功能（用户 2026-10-16 选定）

**R-35 一键申请职位，雇主看申请人列表**
- 验收：职位详情和职位块上有「申请」：带上求职者主页的资料（雇主看到的样子，R-18），可以附一句话（最多 200 字）。同一个职位只能申请一次，可以撤回。未登录时先登录再回来完成申请。求职者「收藏和进度」里，申请过的职位标「已申请」，能看到雇主的处理状态。雇主：职位管理每个职位显示申请人数，点进去是申请人列表（时间、资料要点、附言），可以标「合适 / 不合适」并直接发起聊天；标「不合适」时求职者只看到「雇主已看过」。雇主工作台待办里出现「N 个新申请」，站内通知同步。申请本身不泄露联系方式。被封禁的雇主、已截止的职位不能申请。
- 状态：已做（#91）。申请存在 `job_applications`（迁移 0010），账号 + 职位唯一；雇主只通过随机编号找到申请，看不到邮箱。主页资料只在求职者自己的浏览器里，所以申请时带上一份（名字、一句话介绍、可上班时间、地区、期望时薪、语言、经验、介绍和简历要点），不带头像和联系方式，服务器重新检查和截断。职位详情「立即沟通」旁边是「申请」，职位块「收藏」旁边是「申请」（768 px 起；手机上多一个按钮职位块就要多占一行，一屏放不下三条，所以手机上点职位块进详情页，底部操作栏里有「申请」；申请过的职位块都显示「已申请」）。求职者看到的状态：已申请，等雇主查看 → 雇主已看过（雇主打开过列表，或标了不合适）/ 雇主觉得合适。雇主在职位管理每条点「N 个申请 · M 个新」进入 `/employer/jobs/[id]/applicants`，打开列表就算看过；「发起聊天」开一条只在雇主一方的对话（和推荐人才的对话一样，求职者一方要等聊天双向送达）。导出数据和删除账号包括申请。

**R-36 时薪参考**
- 验收：职位详情显示「同行业、同地区在招职位的时薪」：最低、中位数、最高和样本数；样本少于 5 个时扩大到全奥克兰同行业，再少就不显示，写明「样本太少」。雇主发帖（AI 发帖和表单）填时薪时旁边显示同样的参考，低于中位数时提示一句（只提示，不阻止；低于最低工资仍按合规检查拦下）。只用平台上真实在招的职位，不引用外部数据，写明数据来源和更新时间；不写签证或移民相关的工资门槛。
- 状态：已做（#92）。在服务器上算（`src/lib/pay-reference.ts`，读取时用在招的职位，不存表、不加定时任务）：同一行业，先看同一地区，不到 5 个就看同一大区（全奥克兰），还不到就显示「样本太少」和个数。最低、最高是各职位时薪范围的两端，中位数按每个职位范围的中间值算，不算正在看或编辑的职位本身。入口：职位详情的条件下面；发布表单「工资和福利」的时薪下面；AI 发帖右边的职位卡上（知道行业和时薪后）。

**R-37 中英文简历**
- 验收：「我的主页」里有「生成简历」，用已填的资料生成一页中英文对照简历（称呼、可上班时间、地区、期望时薪、语言、经验、技能、个人介绍）。英文部分只用求职者自己写的英文，缺的字段提示补填，不机器翻译。浏览器「打印 / 存为 PDF」就是成品：A4 一页，不加 PDF 库。简历默认不公开，可以生成只读分享链接（随机编号，随时可以关闭），给不在平台上的雇主看；分享链接不含邮箱，联系方式按求职者勾选显示。签证一项只陈述求职者填写的事实，不写建议。
- 状态：已做（#97）。入口：「我的主页」→「别人看到的样子」旁边的「生成简历」→ `/profile/resume`。页面上是简历本身、「英文还缺 N 项」的提示和补填英文的表单（每项旁边显示对应的中文）、签证（持有的签证和签证上写的每周可工作小时，公民 / 永居不填小时）、勾选印上的联系方式（电话、微信、邮箱，号码来自「私密交换资料」）。地区、用工形式、时薪、每周小时、经验和签证类型是平台固定的选项，用平台自己的英文；求职者写的文字没有英文时只印中文。签证下面印「签证情况由本人填写 / Work rights as stated by the job seeker」。英文、签证和勾选都和主页一样只存在浏览器里。分享时服务器存一份（`resume_shares`，每个账号最多一条，链接编号 18 个随机字节），重新检查和截断，永远不存邮箱；资料改过后页面提示「更新分享内容」，链接不变；关闭就是删除，链接显示「已关闭或不存在」，再分享是新链接。分享页 `/resume/[id]` 不用登录，不收录。导出数据和删除账号包括分享链接。打印时只留下简历本身（页面其余部分、顶栏和底部导航不占位置），e2e 用 Chromium 生成 PDF 确认是一页。
