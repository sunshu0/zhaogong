# 0029 线上数据库：Cloudflare D1

- 状态：已采纳（用户 2026-10-20 23:4x 定的，导师先讲清了代价）
- 日期：2026-10-20（#15）。定下 ADR 0006 留给用户的选择：走选项二。

## 情况

ADR 0006 把线上数据库列成两个选项（Turso、Cloudflare D1），等用户选。

1. **10-20 01:2x：** 用户定了放在境外、跑在 Cloudflare Workers（ADR 0004），不放中国大陆，所以不用 ICP 备案。服务商用户没选，导师先定了 Turso（库放在悉尼）。
2. **10-20 23:4x：** 导师把两边的代价讲清楚以后，用户改成 **Cloudflare D1**。理由：所有东西都在 Cloudflare 一家，只要一个账号，Worker 通过绑定访问库，不用管数据库令牌。
3. **代码现在的样子：** 驱动是 `@libsql/client`（ADR 0005），本机是文件库，测试是内存库。`src/` 里有 19 个文件、约 36 处用了交互式事务（`db.transaction(async (tx) => …)`：取编号再写、团队的改动、删号、外部职位的导入、邀请链接等）。迁移用 `drizzle-kit generate` 生成，本机第一次用时迁移，远程库部署前在本机迁移（#329）。

## 决定

**线上数据库用 Cloudflare D1。** 账号以公司名义注册（用户做）。

- 建库时给位置提示 **`oc`（大洋洲）**：`wrangler d1 create zhaogong --location=oc`。
- Worker 通过 `wrangler.jsonc` 的 `d1_databases` 绑定访问库，没有数据库地址和令牌要保管。
- 迁移用 `wrangler d1 migrations apply`。
- **代码怎么改不在这份 ADR 里定**，留给迁移的 ADR（编号 **0031**，执行 C 10-20 23:4x 登记）：驱动换成 `drizzle-orm/d1`，本机和测试用什么，36 处交互式事务改成 batch 或别的写法，迁移目录怎么接。在那份 ADR 的代码合并以前，代码只会连 libSQL，D1 还用不上，也不部署。

## 代价（照实写）

- **交互式事务要改写。** D1 不支持「开事务、读、按读到的再写、提交」，只能一次提交一批语句（batch）。那约 36 处都要改写成 batch、单条带条件的语句，或者别的做法，每处都要重新测。这是这次决定最大的一笔工作。
- **位置不保证在悉尼。** D1 只能给位置提示：`oc` 是大洋洲，Cloudflare 尽量把库放在那一带，但不保证落在哪个城市，也没有「数据只留在澳大利亚」的司法辖区选项。隐私页里写的「澳大利亚（悉尼）的云服务器」要跟着改（B 的文件，导师另外跟 B 说）；按新西兰隐私法第 11 条，Cloudflare 是替我们保管和处理数据的「代理人」，前提是它不为自己的目的使用这些数据，上线前要在它的条款里核对（导师的法律调研：`D:/dev/zg-scratch/mentor/hosting-legal.md`，仓库外）。
- **国内同事不能直连库。** 10-20 01:2x 用户选了「国内同事可以直连正式数据库」。D1 没有对外的数据库连接，只能在 Cloudflare 后台查，或者用 `wrangler d1 execute` 跑语句。境内的人这样访问，处理活动照样发生在境内，所以《个人信息保护法》仍按适用来做（ADR 0026、`docs/data-breach.md` 不变）。
- **本机和线上可能变成两种库。** 本机和测试继续用 libSQL 文件 / 内存库，还是改用 Wrangler 模拟的 D1，由 ADR 0031 定。
- 好处：一个账号、一张账单，没有令牌要保管和轮换，Worker 和库在同一家网络里。
