# 0014 外部职位：只读官方公开接口，只存事实，先审后显示

- 状态：已采纳（法律部分上线前请新西兰律师审阅）
- 日期：2026-10-17（#111，R-39）

## 情况

用户要在普通工作之外加「实习」「专业职位」两个分区（Round 18）。这些职位不是雇主在找工发布的，而是公司自己招聘系统里的公开职位：求职者在找工用中文看懂、筛选，再「去官网申请」。用户定了四条：只用官方公开接口、遵守法律、先审后显示、第一批只做软件和电子电气。

取职位有几种办法：

1. **抓招聘网站（SEEK、Indeed、LinkedIn）的网页。** 这些网站的条款禁止抓取和转载，也最可能追究；网页结构一改就坏。
2. **抓公司官网的招聘页面 HTML。** 每家页面不同，条款各异，不确定能否转载。
3. **读招聘系统为公开职位提供的官方接口。** Greenhouse 的 Job Board API、Lever 的 Postings API 不要密钥，本来就是给公司在别处展示职位用的，返回结构化数据（职位名、地点、部门、链接，Greenhouse 还有截止日期和薪资范围字段）。

## 决定

1. **只读官方公开接口，先做 Greenhouse 和 Lever。** 不抓 HTML，不登录，不绕过限制。每个接口的主机先读 `robots.txt` 并遵守（RFC 9309：我们的名字 `zhaogong-external-jobs` 的规则优先，其次 `*`；`robots.txt` 读不到 5xx 就不读这台主机）；对同一主机的请求一个接一个，间隔至少 2 秒，主机要求的 `Crawl-delay` 更长时按它；每个请求带 `User-Agent` 说明是谁（`src/lib/external-jobs/polite-fetch.ts`）。
2. **公司名单人工维护，没核对过条款的不读。** `src/config/external-companies.ts` 每家写明招聘系统、接口名称、官网，以及 `terms`：谁、哪天读过这家官网和接口的使用条款、条款是否允许在别处展示职位事实并链接回去。`terms` 为空或不允许的公司，导入时根本不请求它的接口，已有的职位全部下架（`company_off`）。第一版名单里 7 家候选公司（2026-10-17 读过一次各自的公开接口，确认在新西兰招软件或电子电气岗位）**都还没核对条款**，所以现在导入不会取到任何真实职位。
3. **只存事实，原文不入库。** 原文只在导入时读一次，用来找出这些事实：职位名、公司名、地点和城市、领域（软件 / 电子电气）、类型（实习、毕业生项目、全职、兼职、合同）、截止日期、经验年数、学历和专业、签证相关的陈述、薪资（原文写了才有）、官网链接、发布时间、取到时间。表 `external_jobs`（迁移 0016）没有存原文的列，单测检查存下来的数据里没有原文的句子。不翻译原文；中文摘要以后由 AI 按事实写（等 #102 的 key），不逐句翻译。
4. **只写原文写明的，没写就是「原文未说明」。** 类型、截止日期、经验、学历、薪资找不到就是空；签证只认四种陈述：需要公民或居民、需要在新西兰的工作权利、可以担保签证、不能担保签证，一句都没有就是空列表，页面显示「原文未说明」，不推测。年份没写的截止日期按「今天之后最近的那一天」算（往回宽限 30 天，刚过的日期说明已经截止）。截止日期按新西兰当天结束算。
5. **领域和地点在导入时过滤。** 只收新西兰的职位（地点或国家代码），只收软件和电子电气：先看职位名（嵌入式、固件算电子电气），职位名只说「工程师」「实习生」「毕业生」时看部门；销售、技术员、机械、土木等职位名直接排除。其余丢弃，不入库。
6. **先审后显示。** 新导入的职位都是「待审」（`review = pending`），审核员通过后才进分区（#112）。已通过的职位如果职位名、链接或「需审核员留意」的标记变了，回到待审。
7. **标记需要审核员留意的要求。** 要求其他国家公民身份（如出口管制岗位要求 "U.S. person"）或按种族、民族招人的句子标出来（`flags`），由审核员决定；平等机会声明（「不因种族歧视」「欢迎各种背景」）不标。新西兰或澳大利亚公民 / 居民的要求属于签证事实，不标。
8. **下架在读取时判断（同 ADR 0008）。** 显示的条件：审核通过、没有下架、最近 2 天内刷新到过、截止日当天还没过（`src/lib/external-jobs/visibility.ts`）。导入时：接口里没有了 → 下架（`gone`）；截止日已过 → 下架（`closed`）。某家公司的接口读不到时不动它的职位，2 天后自然不显示。
9. **审核后台「外部职位」（#112）。** 待审的职位排在前面，带标记的最先；每条显示事实、「看官网原文」链接，审核员「通过」或「不显示」（选理由：有按国籍、种族招人的要求 / 不是软件或电子电气 / 事实和原文不符 / 其他）。带标记的职位要先勾「我看过原文：这是岗位依法需要的要求」才能通过，服务器上再查一次。已通过的可以「撤下」。公司可以「停用」或记录「公司要求删除」（写明谁提出、内容和日期）：表 `external_company_blocks`（迁移 0018）记一行，同一个事务里把这家所有职位下架，导入器不再请求它；「恢复导入」删掉这一行，它的职位要重新审核。每个操作写一条审核记录（`external_approve` / `external_hide` / `external_stop` / `external_resume` / `external_takedown`），审核数据加「待审核的外部职位」和每位审核员的「外部职位」次数。演示数据里有两家虚构公司（`src/mock/external-jobs.ts`，链接到 example.com），不在名单里，只为了没核对条款之前也能看到页面。
10. **先在本机跑。** 线上服务器还在搁置，导入用 `npm run import:external`（可以只导几家，`--dry-run` 只打印事实不存），上线时再配每天至少一次的定时任务。测试不请求真实接口，用按官方格式手写的夹具（公司是虚构的）。

## 后果

- 不碰禁止转载的网站，不存、不显示别人的原文，每条都写明来源和取到的日期并链接回官网，风险集中在「公司名单」这一处，由人来把关。代价是覆盖面小：只有用 Greenhouse、Lever 的公司，而且要一家家核对条款。以后加 Workable、SmartRecruiters、Ashby 只需要加一个适配器。
- 事实提取是规则，不是理解：可能漏掉写法特殊的截止日期或薪资（显示「原文未说明」），也可能把部门名不清楚的职位分错领域。审核员先审，能挡住分错的。试点后看漏提和误提的情况再调规则。
- 公司要求删除时：把它的 `terms` 改成不允许（或从名单移除），下一次导入当天全部下架；审核后台的处理入口在 #112。
- **这是导师和执行对新西兰法律的理解，不是法律意见。正式上线前请律师看第 2–4、7 条和页面上的来源说明。**
