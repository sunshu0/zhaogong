# 0014 外部职位：只读官方公开接口，只存事实，先审后显示

- 状态：已采纳（法律部分上线前请新西兰律师审阅）
- 日期：2026-10-17（#111，R-39）

## 情况

用户要在普通工作之外加「实习」「专业职位」两个分区（Round 18）。这些职位不是雇主在找工发布的，而是公司自己招聘系统里的公开职位：求职者在找工用中文看懂、筛选，再「去官网申请」。用户定了四条：只用官方公开接口、遵守法律、先审后显示、第一批只做软件和电子电气。

取职位有几种办法：

1. **抓招聘网站（SEEK、Indeed、LinkedIn）的网页。** 这些网站的条款禁止抓取和转载，也最可能追究；网页结构一改就坏。
2. **抓公司官网的招聘页面 HTML。** 每家页面不同，条款各异，不确定能否转载。
3. **读招聘系统为公开职位提供的官方接口。** Greenhouse 的 Job Board API、Lever 的 Postings API 不要密钥，本来就是给公司在别处展示职位用的，返回结构化数据（职位名、地点、部门、链接，Greenhouse 还有截止日期和薪资范围字段）。

## 决定

1. **只读官方公开接口，先做 Greenhouse 和 Lever。** 不抓 HTML，不登录，不绕过限制。每个接口的主机先读 `robots.txt` 并遵守（RFC 9309：我们的名字 `zhaogong-external-jobs` 的规则优先，其次 `*`；`robots.txt` 读不到 5xx 就不读这台主机）；对同一主机的请求一个接一个，间隔至少 2 秒，主机要求的 `Crawl-delay` 更长时按它；每个请求带 `User-Agent` 说明是谁（`src/lib/external-jobs/polite-fetch.ts`）。
2. **公司名单人工维护，没核对过条款的不读。** `src/config/external-companies.ts` 每家写明招聘系统、接口名称、官网，以及 `terms`：谁、哪天读过这家官网和接口的使用条款、条款是否允许在别处展示职位事实并链接回去。`terms` 为空或不允许的公司，导入时根本不请求它的接口，已有的职位全部下架（`company_off`）。第一版名单里 7 家候选公司（2026-10-17 读过一次各自的公开接口，确认在新西兰招软件或电子电气岗位）当时都还没核对条款；同一天审核后只留 ClearPoint 和 MYOB，见文末「补充：第一次条款审核」。从名单删掉的公司，完整导入时它的职位全部下架（`company_off`）。
3. **只存事实，原文不入库。** 原文只在导入时读一次，用来找出这些事实：职位名、公司名、地点和城市、领域（软件 / 电子电气）、类型（实习、毕业生项目、全职、兼职、合同）、截止日期、经验年数、学历和专业、签证相关的陈述、薪资（原文写了才有）、官网链接、发布时间、取到时间。表 `external_jobs`（迁移 0016）没有存原文的列，单测检查存下来的数据里没有原文的句子。不翻译原文；中文摘要以后由 AI 按事实写（等 #102 的 key），不逐句翻译。
4. **只写原文写明的，没写就是「原文未说明」。** 类型、截止日期、经验、学历、薪资找不到就是空；签证只认四种陈述：需要公民或居民、需要在新西兰的工作权利、可以担保签证、不能担保签证，一句都没有就是空列表，页面显示「原文未说明」，不推测。年份没写的截止日期按「今天之后最近的那一天」算（往回宽限 30 天，刚过的日期说明已经截止）。截止日期按新西兰当天结束算。
5. **领域和地点在导入时过滤。** 只收新西兰的职位（地点或国家代码），只收软件和电子电气：先看职位名（嵌入式、固件算电子电气），职位名只说「工程师」「实习生」「毕业生」时看部门；销售、技术员、机械、土木等职位名直接排除。其余丢弃，不入库。
6. **先审后显示。** 新导入的职位都是「待审」（`review = pending`），审核员通过后才进分区（#112）。已通过的职位如果职位名、链接或「需审核员留意」的标记变了，回到待审。
7. **标记需要审核员留意的要求。** 要求其他国家公民身份（如出口管制岗位要求 "U.S. person"）或按种族、民族招人的句子标出来（`flags`），由审核员决定；平等机会声明（「不因种族歧视」「欢迎各种背景」）不标。新西兰或澳大利亚公民 / 居民的要求属于签证事实，不标。
8. **下架在读取时判断（同 ADR 0008）。** 显示的条件：审核通过、没有下架、最近 2 天内刷新到过、截止日当天还没过（`src/lib/external-jobs/visibility.ts`）。导入时：接口里没有了 → 下架（`gone`）；截止日已过 → 下架（`closed`）。某家公司的接口读不到时不动它的职位，2 天后自然不显示。
9. **审核后台「外部职位」（#112）。** 待审的职位排在前面，带标记的最先；每条显示事实、「看官网原文」链接，审核员「通过」或「不显示」（选理由：有按国籍、种族招人的要求 / 不是软件或电子电气 / 事实和原文不符 / 其他）。带标记的职位要先勾「我看过原文：这是岗位依法需要的要求」才能通过，服务器上再查一次。已通过的可以「撤下」。公司可以「停用」或记录「公司要求删除」（写明谁提出、内容和日期）：表 `external_company_blocks`（迁移 0018）记一行，同一个事务里把这家所有职位下架，导入器不再请求它；「恢复导入」删掉这一行，它的职位要重新审核。每个操作写一条审核记录（`external_approve` / `external_hide` / `external_stop` / `external_resume` / `external_takedown`），审核数据加「待审核的外部职位」和每位审核员的「外部职位」次数。演示数据里有两家虚构公司（`src/mock/external-jobs.ts`，链接到 example.com），不在名单里，只为了没核对条款之前也能看到页面。
10. **分区页面（#113）。** `/internships`（实习、毕业生项目）和 `/professional`（其余，包括类型「原文未说明」的）。每条都标「外部职位」和「来自 XX 官网 · 信息取于 X月X日」，职位页只有「去官网申请」，不收录（`noindex`），不放公司 Logo 和招聘人员信息。每页底部是「公司要求删除」的说明和邮箱（`TAKEDOWN_EMAIL`）。
11. **先在本机跑。** 线上服务器还在搁置，导入用 `npm run import:external`（可以只导几家，`--dry-run` 只打印事实不存），上线时再配每天至少一次的定时任务。测试不请求真实接口，用按官方格式手写的夹具（公司是虚构的）。

## 后果

- 不碰禁止转载的网站，不存、不显示别人的原文，每条都写明来源和取到的日期并链接回官网，风险集中在「公司名单」这一处，由人来把关。代价是覆盖面小：只有用 Greenhouse、Lever 的公司，而且要一家家核对条款。以后加 Workable、SmartRecruiters、Ashby 只需要加一个适配器。
- 事实提取是规则，不是理解：可能漏掉写法特殊的截止日期或薪资（显示「原文未说明」），也可能把部门名不清楚的职位分错领域。审核员先审，能挡住分错的。试点后看漏提和误提的情况再调规则。
- 公司要求删除时：把它的 `terms` 改成不允许（或从名单移除），下一次导入当天全部下架；审核后台的处理入口在 #112。
- **这是导师和执行对新西兰法律的理解，不是法律意见。正式上线前请律师看第 2–4、7 条和页面上的来源说明。**

## 补充：第一次条款审核（2026-10-17）

用户 2026-10-17 让找工导师（Claude）代为审核名单上 7 家公司的条款，没问题的就放。结论在 `src/config/external-companies.ts` 每家的 `terms` 里（谁、哪天、读了哪些条款）。**这是导师的审核，不是法律意见**，上线前请律师看的范围不变。

**标准：** 公司官网的条款和招聘系统（Greenhouse / Lever）的条款里，都没有禁止或限制第三方复制、展示、抓取、深链的条款，才算可以放。只要写了「须书面许可」或「禁止」，就不放。

**招聘系统这一层：** Lever 的接口文档写明已发布的职位公开可见，「may be scraped by third parties」；开发者用例写明招聘网站可以读客户的公开职位 feed；它的 Terms of Service 约束的是付费客户，没有关于抓取或转载职位的条款；`jobs.lever.co`、`api.lever.co` 的 `robots.txt` 是 `Allow: /`、`Crawl-delay: 1`。

| 公司 | 结论 | 依据 |
| --- | --- | --- |
| ClearPoint（Lever `clearpoint`） | 可以放 | 官网只有隐私政策，没有使用条款，没有关于复制、抓取、链接的限制。 |
| MYOB（Lever `myob-2`） | 可以放 | 新西兰和澳洲官网的使用条款只限制软件的复制和再分发，没有关于网站内容转载、抓取、链接的条款。 |
| Rocket Lab | 不放 | 复制、转载、发布内容须书面许可。 |
| Pushpay | 不放 | 网站内容未经事先签字的书面同意不得复制或再发布。 |
| Propellerhead | 不放 | 不得复制、展示、发布；不许用机器人收集信息；深链须书面同意。 |
| KPMG New Zealand | 不放 | 不得为公开或商业目的复制、公开展示内容；有链接限制。 |
| Dawn Aerospace | 不放 | 禁止商业复制、数据挖掘和机器人，只许链接到首页。 |

**用户决定：** 只保留 ClearPoint 和 MYOB，另外 5 家从名单删掉，不去要书面许可，暂时不扩大名单。以后要加回来，先拿到书面许可，再按上面的标准写 `terms`。

**放上去以后：** 2026-10-17 的 dry run 里，ClearPoint 留下 3 条（奥克兰、惠灵顿的合同制高级工程师意向登记），MYOB 留下 1 条（奥克兰的 Engineering Manager），其余不在新西兰或不是软件、电子电气。导入以后照第 6 条，审核员在「外部职位」里逐条通过才显示。

## 补充二：第三个来源 Ashby（2026-10-17，#138）

第一次审核后名单上只剩 4 条职位。执行 C 调研后发现，新西兰的软件公司大多不用 Greenhouse 和 Lever，而是用 Ashby（Halter、Xero、Partly、Auror）。用户同意加上 Ashby，条款仍由找工导师代为审核。调研记录在仓库外：`D:/dev/zhaogong-external-candidates-2026-10-17.md`（第二轮）。

**口径（导师 2026-10-17 定，沿用第一次的先例）：** 只约束付费客户、或者只限定在产品上的条款，不算对网站和招聘页的限制。第一次的 MYOB 就是因为只限制软件，才算可以的。

**招聘系统这一层：** Ashby 的公开 Job Postings API（`https://api.ashbyhq.com/posting-api/job-board/<name>`）不要密钥。文档说它给公司自己的招聘页用（「If you host your own careers page, you can use this data to populate it」），没有禁止第三方读取。Ashby 的 Terms of Service 是「Ashby Customer Terms of Service」，只约束付费客户。`jobs.ashbyhq.com` 的 `robots.txt` 只挡 `/meeting/`、`/b/`、`/api/`。`api.ashbyhq.com` 的 `robots.txt` 回 401，按 RFC 9309 等于没有。

| 公司 | 结论 | 依据 |
| --- | --- | --- |
| Halter（Ashby `halter`） | 可以放 | 官网没有网站使用条款；服务合同和 Software Usage Policy 限制的都是「the Software Services」里的内容。 |
| Partly（Ashby `partly.com`） | 可以放 | 官网没有网站使用条款；End User Agreement 禁止抓取的是「the Services, or information featured in it」。 |
| Auror（Ashby `auror`） | 可以放 | 官网没有网站使用条款；平台用户条款禁止抓取、深链的都是「on the Platform」。 |
| Xero | 不放 | 官网唯一的使用条款写了不许复制「any of our content」，没有限定在产品上。 |
| Lightspeed | 不放 | 网站内容受版权保护，没有许可不得复制、展示。 |

**导入器：** 第三个适配器 `parseAshby`（`src/lib/external-jobs/sources.ts`）。地点取 `location`、`address` 和 `secondaryLocations`；只有每个地址都在新西兰时，才记国家为 NZ。部门取 `department` 和 `team`，`employmentType` 当用工形式，薪资取 `compensation.summaryComponents` 里的 Salary。**`isListed: false` 的职位跳过**：Ashby 文档说这种职位只许直链，公司没把它列在自己的招聘页上，我们也不列。事实规则（第 2–4 条）和先审后显示（第 6 条）不变。

**放上去以后：** 2026-10-17 用真实接口 dry run，Halter 284 条里留下 28 条（软件 22、电子电气 6，都在奥克兰），Partly 34 条里留下 11 条（基督城、奥克兰），Auror 13 条里留下 4 条（奥克兰和新西兰远程，写了薪资）。Partly 有 1 条产品经理职位因为标题里有 Developer 被算成软件，审核员会看到。

**分类的两处调整（#180，2026-10-18）：**

- 职位名笼统、部门或小组只写「Engineering」时，Ashby 上算软件。Xero 在新西兰的 4 条工程岗原来因此丢掉；Halter 的硬件岗在单独的「Hardware」部门，存下的 284 条重算后仍是 28 条。Greenhouse 和 Lever 上的公司怎么写部门还没核对过，照旧不算。
- 产品经理、产品负责人、产品设计师和 business developer 不算工程岗位。「Developer Ecosystem」「Developer Relations」这类说职位面向谁的词，不算 Developer。上面那条 Partly 的产品经理因此不再收进来，Partly 预计 10 条。
