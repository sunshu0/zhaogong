# 0044 企业可以暂时封禁：到期自动恢复，期间不下架、只是看不到

- 状态：已采纳（导师 local_573a9208 定的默认，说明 `zg-scratch/mentor-573a/brief-A-07.md`；执行 A local_c3fc9602 起草）
- 日期：2026-10-27。Issue #401。用户 10-27 00:5x：「我看到审核员处理举报好像只有下架职位和封禁雇主 我觉得可以加入临时封禁」；01:0x「临时封禁照你定的默认做。」

## 情况

审核员处理举报只有两个办法：下架一个职位，或者永久封禁企业（全部职位下架，再也不能用）。轻一些的违规（比如一次说了押金、回复里态度恶劣）没有中间档。

## 决定

### 1. 存法：`banned_until` 为空就是永久

`employers` 加 `banned_until` 和 `ban_reason`（迁移 0039）。`banned_at` 有值、`banned_until` 为空 = 永久；两个都有 = 暂时，到 `banned_until` 为止。审核记录 `moderation_log` 加 `ban_days`（封了几天），原因放在原有的 `note`。

`ban_reason` 是说明文件里没有的一列：雇主的团队要看到原因，只放在审核记录里的话，每次显示都要去翻记录。

### 2. 到期不用谁去点：每次读的时候按时间判断

到期那一刻什么都不写。凡是判断「被封了没有」的地方都问 `isBanned(employer, now)`（`src/lib/employer-ban.ts`），SQL 里用 `employerNotBannedSql`（`src/db/bans.ts`），规则一样：`banned_at` 为空，或者 `banned_until` 已经到了，就是没封。

- 页面用 `requestTime()` 的时间；服务器动作用 `Date.now()`；没有请求时间的快照（首页统计、预渲染的精选）把所有封禁都算上，暂时的也算，宁可少显示。
- 服务器把企业交给浏览器之前过一遍 `currentBan`：已经到期的封禁字段去掉。所以浏览器里的 `bannedAt` 就是「现在被封着」，浏览器不读时钟（避免服务器和浏览器算出来不一样）。
- 并发的写（开雇主身份、加入团队）在 SQL 条件里按同一个时间判断，团队的乐观锁指纹带上 `banned_until`。

### 3. 暂时封禁不下架

职位的 status 不改，只是期间对外看不到：职位列表、首页精选和统计、站点地图、企业主页、职位详情（当作不在了）、收藏和申请（当作不在了）都按 `isBanned` 排除。到期自动重新出现（没过截止日期的），截止日期不顺延。

为什么不下架：下架了到期还得一个个恢复，而且分不清哪些是因为封禁下架、哪些本来就是审核员下架的。触发这次封禁的那条被举报的职位，审核员要下架就另外点「下架职位」。

永久封禁照旧下架全部。暂时改成永久时也下架全部。

### 4. 期间企业一侧：和永久封禁走同一条路

`getAccountEmployer` 对被封的企业（暂时的也一样）不给，所以发、改职位，聊天，团队这些写操作全都停，一处不用单独挡。页面上的封禁提示改成写明到什么时候、原因是什么、期间不能做什么、到期自动恢复（`src/components/employer/ban-notice.ts`）；永久的照旧那句话。

代价：期间团队也看不到自己的职位和候选人（和永久封禁一样）。说明文件写的是「后台顶上一条提示」，这里取了更稳的做法，见汇报。

### 5. 期间聊天：两边都停

雇主那边不能发（第 4 条）。求职者那边不能对这家开新对话，也不能在已有的对话里发，对话里写「对方暂时不能回复」。为什么两边都停：封禁多半是因为骗人或违规招人，求职者继续发消息，就是继续被拉过去。

### 6. 审核后台

- 处理举报时「封禁雇主」先选：暂时 3 天、7 天、30 天（要写原因，最多 200 字，雇主的团队会看到），或者永久（照旧下架全部）。什么都不选时确认按钮是灰的，按一次不会误封。
- 「记录与统计」加「暂时封禁」：正在封的企业，最先到期的在前；到什么时候、原因、谁封的；「提前解除」「改成永久」。
- 审核记录加三种：`temp_ban`、`unban`、`make_permanent`。
- 永久封禁这次不加解除（用户没提）。

### 7. 条款

条款「我们可以停用账号或封禁企业」后面加「（可以是暂时的，也可以是永久的）」，中英文，日期改 10-27。这不是对用户不利的修改（多了一个比永久轻的办法），所以不用提前通知。隐私页没有讲封禁，不改。

## 不做

- 永久封禁的解除；封求职者；自动封禁；改举报流程。

## 后果

- 新代码判断封禁一律用 `isBanned` / `employerNotBannedSql` / `currentBan`，不要直接看 `bannedAt`。
- 测试里要把封禁「拨到期」，用开发用的接口改 `banned_until`（和改职位截止日期的 `/api/dev/job-closing` 一样）。
