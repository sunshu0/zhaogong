# 0022 企业主页存到服务器，属于企业，只有管理员能改

- 状态：已采纳
- 日期：2026-10-18（#181）。补充 ADR 0012（雇主多人管理）、ADR 0017（求职者主页存在账号上）、ADR 0009（删除账号）

## 情况

企业主页（`/profile` 的雇主身份，公开页 `/employers/[id]`）一直只存在各人浏览器的 `zhaogong:profiles-by-identity` 里（ADR 0001 当时的做法）。这样有三个问题：

- 求职者看不到。公开页读的是「这个浏览器里有没有这家企业的主页」，别人的浏览器里从来没有，所以对求职者来说，企业介绍、招聘联系人永远是「雇主尚未填写」。
- 团队对不上。#87 之后一家企业可以有几个人，每人浏览器里各一份，改了也互相看不到。ADR 0012 因此把「只有管理员能改企业资料」记成了还没做。
- 换设备、清缓存就没了。求职者主页在 #104 存到了账号上（ADR 0017），企业主页还没有。

## 决定

1. **一家企业一条。** 新表 `employer_profiles`（迁移 0022）：`employer_id` 是主键，`page` 存改过的内容（和浏览器存的形状一样，只留公开的几项），`updated_at` 是最后一次保存，`updated_by_email` 是谁存的。
2. **只存公开的几项。** 名称、招聘简介、地区、招聘联系人、沟通语言、联系时间、企业介绍、头像（`EMPLOYER_PAGE_FIELDS`）。服务器用 `parseEmployerPage` 重新解析（逐项检查，和求职者主页同一套），整份超过 250 kB 就拒绝。**私密交换资料不上服务器**：那是每个人自己的电话、微信，在聊天里交换时给对方，团队里每人一份，还是只存在自己的浏览器里。
3. **读：团队里每个人和所有访客；写：只有管理员。** 权限写在 `team.ts`（`teamCan(role, "page")`，管理员才有），保存时在写入的同一个事务里再查一次（`saveEmployerPage`）。#87 之前的账号没有 `team_role`，照别处的做法算管理员。成员打开 `/profile` 看到的是服务器上那份，企业的字段都不能改（`fieldset disabled`），顶上写明「企业主页只有管理员（某某）能改」；他自己的私密交换资料照常能改。成员送来的保存，服务器原样不动，回答里带 `canEdit: false`，浏览器从此按只读显示。
4. **管理员的同步照 ADR 0017。** 页面照旧先改本机副本，再把整份企业的那几项送到服务器，一次一个。每次打开页面先比一次（`syncStep`）：服务器上还没有、本机有，就上传——**这就是浏览器里旧的那份第一次带上去**；本机没有就用服务器的；两边不一样又说不清谁新，就问「用企业主页现在的」还是「用这台设备上的」。比较只看企业的那几项，私密交换资料不参与。
5. **成员浏览器里旧的那份不动。** 成员不能写，所以不上传；也不拿服务器的去覆盖，本机副本原样留着（「数据与账号」照旧能导出）。页面显示时用服务器的那几项盖在上面。服务器上还没有主页、只有某个成员本机填过的情况，要管理员来填。
6. **公开页和头像读服务器。** `employerPublicPages(ids)`：给任何人，一次最多 50 家，被封禁的企业和还没有主页的企业不在回答里。浏览器每次打开页面按企业问一次，同一时刻要的几家（比如聊天列表里的几家）合成一次问（`public-pages-client.ts`）。服务器还没回答时，用这个浏览器自己那份顶着（只有这家企业的人才有）。管理员保存后，下次看公开页重新问。
7. **删除账号（补充 ADR 0009、0012）：** 存过主页的人删号，主页留着，`updated_by_email` 换成 `deleted-account`。企业最后一个人删号时，主页跟着删掉（没人维护了，公开页只剩企业名称和资质）。导出数据里，企业那一节带上企业主页，并写明最后一次是不是自己存的。防漏单测加上了这一列。

## 后果

- 求职者第一次能在公开页上看到企业自己写的介绍、联系人和头像；团队里每个人看到的是同一份。
- 只有管理员能改企业主页，ADR 0012「还没做」里的这一条做完了。成员想改，要请管理员改，或者请管理员把自己设为管理员。
- 两位管理员同时改，后送到的那份覆盖前一份，不按字段合并（和 ADR 0017 一样，企业主页一般一个人改）。
- 公开页的企业介绍还是浏览器取来的，关掉 JavaScript 时看不到；要放进服务器渲染，等 A 线这一轮公开页改版合并后再做。
- 职位记下是谁发的（ADR 0012 后果里写的另一条）是 #182。
