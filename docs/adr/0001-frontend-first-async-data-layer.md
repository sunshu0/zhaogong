# 0001 先做前端，服务器数据走异步的 data.ts

- 状态：已采纳；阶段三按此换成数据库（2026-10-15 用户决定做完整产品）
- 日期：2026-10-11（`c8c565d`）

## 情况

项目开始时要尽快让人看到、用到产品：两条执行线并行做求职端和雇主端，没有后端。如果页面直接读演示数组，以后接数据库要改遍所有页面。

## 决定

- 所有服务器数据只经过 `src/lib/data.ts` 的函数：`listJobs`、`getJob`、`createJob`、`updateJob`、`submitReport`、`getAccountEmployer` 等。
- 函数一律是 `async`，签名按数据库调用设计（按编号取、按条件列、写入返回新记录），现在的函数体读写进程内存。
- 演示数据放在 `src/mock/`，只由 `data.ts` 读取。
- 加字段、加函数算改共享文件，要在队列里申请（`CLAUDE.md`）。

## 后果

- 好处：页面和 Server Functions 不知道数据在哪；阶段三只换 `data.ts` 的函数体，单测改为对临时数据库跑。
- 代价：内存数据在服务器重启或 Cloudflare 多实例之间不共享，演示站上发布的职位可能丢（`docs/cloudflare-deployment.md`）。
- 只属于一个用户的数据（聊天、主页、通知已读）当时放在浏览器本机，不在 `data.ts` 里；阶段三的 A12-2 把它们搬到服务器。求职者主页 #104 搬到服务器（ADR 0017），企业主页还在浏览器。
