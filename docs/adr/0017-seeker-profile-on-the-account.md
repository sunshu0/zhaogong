# 0017 求职者主页存在账号上，浏览器留一份副本

- 状态：已采纳
- 日期：2026-10-17（#104）

## 情况

求职者的「我的主页」原来只存在浏览器的 `zhaogong:profiles-by-identity` 里（ADR 0001 当时的做法）。换手机、清缓存，主页就没了。雇主的推荐人才也只能看到同一个浏览器里的主页，申请（#84）和简历分享（#86）各自在服务器上存一份快照。

## 决定

1. **一个账号一条。** 表 `seeker_profiles`（迁移 0019）：账号邮箱是主键，`profile` 存用户改过的内容，和浏览器存的形状一样（`parseProfilePatch`）。服务器用同一个函数重新解析，不信浏览器，整份超过 250 kB 就拒绝。存改动而不是整份主页，是因为现在新账号的主页默认值还是演示人物。等默认改成空主页以后，改动就是整份主页，表不用改。
2. **只有求职者身份。** 企业主页还在浏览器里。它是企业的，属于团队（ADR 0012），要另外设计。
3. **浏览器留一份副本，先存本机再送服务器。** 页面照旧读本机副本，所以连不上服务器时也能改。每次改动先写本机，再把整份主页送到服务器。一次只送一个，送的过程中又改了，就等这次回来再送一次，所以最后送到的就是最新的。没有用聊天那样的待发送队列（`chat-outbox.ts`）：主页只有一份，整份覆盖就够了，不需要按改动编号去重。
4. **每次打开页面先和账号比一次**（`profile-sync.ts` 的 `syncStep`，纯函数，有单测）。浏览器为每个身份记两件事（`zhaogong:profile-sync`）：本机副本上次和账号对上时账号的保存时间 `at`，以及有没有还没确认的改动 `dirty`。
   - 账号里没有、本机有：上传，这是 #104 之前就在用的人。
   - 本机没有：用账号的，这是新设备。
   - 一样：什么都不做。
   - 不一样，账号的保存时间等于 `at`：本机是从账号当前那份改过来的，上传。
   - 不一样，账号在别处改过，本机没有新改动：用账号的。
   - 其余情况（这台设备从没和账号对上过、两边都改过）：**问用户**，「用账号里的」或「用这台设备上的」。选好之前不往服务器送，免得一台新设备上的旧资料直接盖掉账号里的。比较完之前的改动只标记，不送。
5. **导出和删除账号包括 `seeker_profiles`**（ADR 0009），防漏单测里加上了这个邮箱列。浏览器里的副本照旧由「数据与账号」页导出和清除。

## 后果

- 换设备、清缓存不再丢主页。连不上服务器时页面写明改动只在这台设备上，下次改动或下次打开时再送。
- 两台设备同时改，后送到的那份覆盖前一份，不合并字段。主页一般一个人改，按字段合并的复杂度不值得。
- 第二部分：推荐人才从账号读（`recommendedCandidates`，只给雇主身份，只带公开字段），申请时用账号里的主页做快照。e2e 里的测试账号也会出现在别的企业的推荐人才里，所以数推荐人数的测试只数演示候选人，打开「允许推荐」的测试在结束前关掉它。
