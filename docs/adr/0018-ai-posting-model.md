# 0018 AI 发帖接入 Claude：模型听懂和追问，规则把关，失败就说不可用

- 状态：已采纳
- 日期：2026-10-17（#102，R-11）

## 情况

「对话发布」原来是按规则写的脚本（`nextTurn`）：固定顺序一项项问，答案用规则解析。用户 10-17 决定 AI 发帖要真的接入大模型，不能只靠脚本。同时要守住三件事：合规检查（R-13）不能被模型绕过；没有 key、超时或出错时不能悄悄退回脚本冒充 AI；费用和滥用要有上限。

## 决定

1. **模型和服务商：** Anthropic Messages API，模型名读 `AI_POST_MODEL`，默认 `claude-sonnet-5-5`（对话短、要快，每轮只需要听懂一两句话）。effort 用 `low`。开启服务器端的拒答兜底（`fallbacks: "default"`）。每次请求最多 20 秒，失败重试一次。
2. **结构化输出，不从自由文本里猜。** 每一轮模型交回一个 JSON 对象（`output_config.format`）：下一句话、最多 4 个快捷回复、这一轮确定的草稿字段。字段是平铺的（时薪写成 `payMin`/`payMax`），22 个可选字段，没有联合类型，在结构化输出的限制以内（可选字段最多 24 个，联合类型最多 16 个）。
3. **规则有最后一句话。** 模型交回的字段和浏览器传来的一样，先经过 `sanitizeDraft`，再跑 `checkJob`。模型写进来的新问题，用规则自己的话接在模型的回答后面说出来；「预览并发布」只在必填齐全、规则放行时由服务器加上；发布时 `publishJob` 还会再检查一遍。模型在提示里知道平台规则，但规则不靠模型执行。
4. **发给模型的内容：** 固定的系统提示（缓存），从雇主第一句话开始的对话，最后一条是平台附注（当前草稿、还缺的必填项、规则发现的问题），用对话中的 system 消息，不算雇主说的话。不发账号邮箱、店名以外的账号信息。
5. **谁在回答：** 生产环境只有模型。没配 `ANTHROPIC_API_KEY`、超时、出错、被拒或答案读不出来时，对话里说「AI 发帖助手暂时不可用」，给「改用直接填表」，不退回脚本。开发和测试环境默认用规则脚本，页面上写「开发环境：脚本助手，不是 AI。」；`AI_POST_LIVE=1` 且有 key 时才调用真模型（开发机上可能有给别的工具用的 key）；`AI_POST_FAKE=1` 或浏览器带 `zg_ai_fake=1` cookie 时用固定回答的假模型，测试模型那条路。首页的「真实对话回放」继续用脚本。
6. **key 只在服务器：** 只读服务器环境变量（生产环境是 Cloudflare secret），不进前端和仓库。客户端固定访问 `https://api.anthropic.com`，不吃本机为别的工具设置的 base URL；`AI_POST_BASE_URL` 可以覆盖。
7. **限额和用量：** 调用模型要登录；没登录时对话里说「登录后才能用 AI 发帖助手」，给「改用直接填表」（填表不用登录就能写，发布前再登录）。每个账号每分钟 6 次、每天 100 次（最近 60 秒、最近 24 小时，不按自然日），只有 Claude 和测试用的假模型计数，脚本不计。在 `chatTurn` 里、真正调用模型之前检查（`modelTurn` 的 `limit`），所以空消息和服务器直接给出的「预览并发布」不算一次。超了不调用模型，对话里说稍后再试或明天再继续，给「改用直接填表」。每次调用在 `ai_usage` 表（迁移 0020）记一行：账号邮箱、时间、模型、输入 / 输出 / 缓存读 / 缓存写 token、结果（`ok`、`error`、`refused`、`unreadable`；被限额挡下的记 `limited`，不算进限额本身）。限额就按这张表数。同一账号同时发两句时，两次检查可能都通过，最多多出一两次；这是软上限，不加锁。审核数据里有「AI 发帖用量」：最近 7 个新西兰日每天的调用次数、token 合计、失败次数和超限次数，只有合计，不显示是谁。导出我的数据里有自己的用量；删除账号后用量记录保留，邮箱换成 `deleted-account`，和审核记录一样。

## 后果

- 雇主可以用自己的话说，不用按固定顺序回答；问到的内容由模型决定，所以 e2e 不能断言模型的原话，只用假模型测周边的逻辑。真实效果用 `npm run ai:smoke` 手动看。
- 没有 key 的生产环境不能用对话发布，只能直接填表。这是有意的：用户不想要冒充 AI 的脚本。
- 每轮都要等一次模型调用（通常几秒），比脚本慢。
- 模型偶尔会问得不合适或漏问，但写不进违规的内容，也越不过「预览并发布」的门槛。
- 一个账号一天最多花 100 次调用的钱。按每次几千 token 的输入（系统提示走缓存）算，单个账号的费用有上限；全站的总费用看审核数据里的 token 合计，需要时再加全站上限。
- 没登录的人在生产环境不能用对话发布，只能直接填表。

## 补充（2026-10-23，上线前安全检查第二节 B 条）

检查发现两个能让一个账号花超的口子，已改：

- **先占位，再调用。** 原来是先数这个账号最近一分钟、24 小时的调用次数，模型回答后才记一行，同时发来的请求都能通过检查。现在调用前先用一条语句插一行 `pending`，插入的条件就是「最近一分钟少于 6 次、24 小时少于 100 次」（ADR 0031 的 `insertIf`），插不进去就是到了上限，照旧记一行 `limited`；模型回答后把这一行改成 `ok` / `error` / `refused` / `unreadable` 并填上 token。服务器在调用中途停了，这一行留着 `pending`，照样算次数，审核数据里算失败。
- **发给模型的对话截短。** 浏览器最多能送来 200 条、每条 4,000 字，原来全部发给模型。现在只发最近 30 条、合计不超过 12,000 字，从雇主的一句开始，最新一句总在（`turn.ts` 的 `recentHistory`）。草稿每轮都随系统说明一起发，前面谈定的不会丢。
- **没有改成只许雇主身份用。** 开通雇主身份是免费的、一步就成，挡不住想花钱的人，反而让先试试的人多走一步；次数上限按账号算已经够了。
