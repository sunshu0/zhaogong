# 0013 岗位类别：职位和求职者按类别比较，不再靠关键词

- 状态：已采纳
- 日期：2026-10-17（#96，R-17）

## 情况

推荐人才的「岗位与技能」一项（权重 30）原来用 `candidate-matching.ts` 里一张 19 个关键词的表：职位文字和求职者资料里都出现同一个词才算对口。用户 10-17 指出，同一个岗位叫法很多，前台、服务员、前厅、接待都是一类。表里少一个叫法（跑堂、传菜），求职者就被漏掉或分数偏低。

## 决定

1. **一张类别表。** `src/config/job-roles.ts` 列出 18 个类别，每个类别有中文名、英文名、所属行业（可以几个）和常见叫法（中文按原样，英文小写）。增删只改这一处；`docs/job-roles.md` 给人看，单测检查两边一致。
2. **职位带类别，最多两个。** `jobs.roles` 存类别编号的 JSON 数组（迁移 0014）。雇主选的优先；没选时由 `suggestJobRoles` 按职位名的中英文归类，**只认职位所属行业里的类别**：餐厅的「前台」是前厅服务，办公室的「前台」是办公文员，奶茶店的「店员」不是零售的理货店员。行业是「其他」时，所有类别都算。一个也认不出时，存空数组，就是「待选」。
3. **已有职位由迁移补上。** 0014 先加一列可空的 `roles`（按 0005 的约定，不用 SQL `DEFAULT`），全部置为 `[]`，再按表的顺序对每个类别执行一条 `UPDATE`：行业对得上、职位名里有它的叫法、而且还不满两个，就追加进去。这和 `suggestJobRoles` 是同一条规则；SQL 是从当时的表生成后固定在迁移里的，迁移测试拿全部演示职位核对两边的结果。以后改表不会改到旧迁移。新数据库的演示数据在 `seedDemoData` 里用 `suggestJobRoles` 填。
4. **求职者勾选想做的类别**（`Resume.roles`，个数不限）。没勾选的旧资料，从一句话介绍、自我介绍和技能里找同样的叫法，前面有「不会」「没有」的不算。说明里写「资料提到」，以区别于勾选的「都选了」。
5. **怎么算分：** 求职者的类别包含职位的类别，满分；求职者的类别属于职位所在的行业，一半；不同行业，0 分；求职者两边都没有，待补充；职位没有类别，这一项不计。原来的关键词表只用来在说明里补一句「技能：点餐、收银」，不再影响分数。「相关经验」也改成看类别是否对口。

## 后果

- 加一个叫法就能让所有职位和资料按它匹配，不用改匹配代码。
- 自动归类只看职位名。名字里没有叫法的职位是「待选」，要雇主补选（发帖和职位管理的界面在 #96 的第二部分）。
- 一个求职者可以勾很多类别，一样拿满分，因为「想做」本来就可以有很多；雇主仍然可以看其他几项（经验、地区、工时）来区分。
- 以后接入 AI 服务商，可以让它建议类别，但只做建议，由雇主或求职者确认，不直接算分。
