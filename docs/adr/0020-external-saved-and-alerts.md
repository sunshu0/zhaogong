# 0020 外部职位的收藏和提醒：新表，提醒表加分区

- 状态：已采纳
- 日期：2026-10-17（#131，R-28、R-29、R-39）

## 情况

「实习」「专业职位」（#113，ADR 0014）上线时不能收藏，也不能设提醒：`saved_jobs`、`job_alert_hits` 的 `job_id` 都是指向 `jobs` 的外键，外部职位在另一张表 `external_jobs` 里，编号的写法也不同（`<公司>:<来源里的编号>`）。`job_alerts` 存的是职位列表的筛选条件，分区的筛选条件不一样（领域、类型、经验、签证、地区、写了薪资）。

能选的做法：给旧表加一列「外部职位编号」，`job_id` 改成可以为空；或者另开新表。SQLite 改不了已有列的外键和非空约束，只能重建整张表，主键（账号 + 职位）也要跟着改。

## 决定

1. **收藏另开一张表 `saved_external_jobs`**（迁移 0021）：账号 + 外部职位为主键，带收藏时间、进度和改进度的时间，和 `saved_jobs` 一样。外部职位没有聊天，进度只能自己选，没选时是「已收藏」。只能收藏分区里正在显示的职位（等审核的不让收藏）；收藏以后职位不显示了（撤下、公司停用、超过 2 天没刷新、过了截止日），照样列在「收藏和进度」里，标「已下架」。
2. **页面上和普通职位共用一套。** 收藏按钮、`mySavedJobIds`、`saveMyJob`、`unsaveMyJob`、`setMyJobStage` 都不分家：外部职位用 `external:<编号>` 作收藏的键（`externalSaveKey`），普通职位的编号不会这样开头。「收藏和进度」把两种按收藏时间排在一起，外部职位标「外部职位」，点开到 `/external/<编号>`。
3. **提醒还是 `job_alerts`，加一列 `section`**：空 = 职位列表的提醒（#53），`internship` / `professional` = 分区的提醒，`query` 存分区的筛选条件（`externalFilterToQuery`，键按表单的顺序，读取时用 `parseExternalFilter`，未知的值丢掉）。加一列可以为空的列，旧数据不用动。两种提醒合计每个账号最多 5 个，「职位提醒」里一起管理。同一个分区、同样的条件存两次还是原来那一个。
4. **提醒找到的外部职位记在新表 `external_job_alert_hits`**：账号 + 外部职位为主键，同一个职位对同一个人只提醒一次，撤下后再通过也不会再提醒。
5. **什么时候匹配：** 审核员在「外部职位」点「通过」的时候（`approveExternalJob` → `matchExternalJobAlerts`），这时职位才开始显示。导入不匹配：导入的职位都要先审。职位列表的提醒只匹配 `section` 为空的，分区的提醒只匹配同一分区的外部职位（类型没写的属于「专业职位」，和分区页面一样）。外部职位不属于任何账号，不用排除发布者。
6. **通知：** 求职者身份的「通知」里一条「有外部职位符合提醒「名称」」，写公司和职位名，编号 `alert:external:<编号>`，点开到职位页；职位不显示以后写「已经下架」。
7. **账号数据：** 导出包括外部职位的收藏、提醒的分区和外部职位提醒记录；删除账号时一起删（ADR 0009）。

## 后果

- 两张收藏表、两张提醒记录表，读「收藏和进度」和「通知」时各查一次再合在一起。数量很小（每个账号几十条），不影响速度。
- 外键还在：外部职位的行不删（ADR 0014 下架只是标记），所以收藏和提醒记录不会指向不存在的职位。以后要真删外部职位，先删这两张表里的行。
- 公司要求删除时，这家的职位当天下架；已收藏的人在「收藏和进度」里还能看到职位名，标「已下架」，没有链接。
- 邮件提醒和普通职位一样，等邮件服务（#16）。
