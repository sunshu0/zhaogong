# 0030 候选人改成「这个职位聊过的人」：申请表当候选人表，聊天里说了话就有一行，不带主页

- 状态：已采纳（用户 10-20 11:0x 定方向；导师 12:5x 定做法：复用申请表，`profile`、`note` 改成可空；导师 14:0x 定「我的申请」也列 chat 行）
- 日期：2026-10-20。编号：ADR 0030、迁移 0030（执行 C 11:5x 登记）。

## 情况

1. **用户 10-20 11:0x：** 职位页的「申请」按钮删掉（A 的 #352），雇主的候选人列表改成「这个职位聊过的人」；聊天里也能标「合适 / 已录用」；录用和职位结束的通知照旧；已有的申请记录留在「我的」里可看。
2. **雇主端每样都按申请编号走：** 候选人列表和合适 / 不合适 / 已录用（`applicant-actions.ts`）、约面试（`interviews.application_id` 非空、唯一，指向 `job_applications.id`）、求职者的「已录用 / 招满 / 已结束」通知（`me/application-notifications.ts`）、职位数据的漏斗、职位管理的计数。
3. **对话按（求职者、企业、职位）唯一**，跟申请（求职者、职位）是同一件事的两面。

## 决定

### 1. 申请表当候选人表，加 `source`

- 迁移 0030：`job_applications` 加 `source`（`apply` 申请 / `chat` 聊过，默认 `apply`）；`note`、`profile` 改成可空（SQLite 改可空要重建表，迁移里照 drizzle 的重建写法做，面试的外键不受影响）。
- **chat 行不带主页、不带附言，存 null**，不塞假的空主页：求职者没把主页交给雇主（ADR 0002）。卡片、通知、导出都按 null 处理，名字用聊天里雇主看到的那个（求职者主页上现在的名字，没有就是对方被找到时的名字，再没有就写「求职者」）。
- 为什么不在对话上加 `decision`、面试表加 `conversation_id`：面试、通知、漏斗、计数都按申请编号，那样要重建面试表、改两套读法；复用申请表这些都照旧走，只改了读名字和主页的几处。

### 2. 什么时候算「聊过」

- **第一条消息发出时**（哪一方先说都算），在同一个事务里插一行 `chat`，已经有申请的不动（`addSharedMessage` → `addChatCandidate`）。只点开「立即沟通」、谁也没说话，不算：那只是看了一眼（跟 `sharedPart` 里「对方没说话不出现在对方列表」一致）。
- 雇主在聊天里先标记（还没人说话）时也插一行，标记要有地方存。
- chat 行建的时候就算「看过」（`seen_at` = 建的时间）：雇主在聊天里已经看到了。所以职位卡和总览待办的「N 个新申请」只数申请，雇主的「X 申请了」通知也只对申请。
- 迁移回填：已有消息、没有申请的对话，各插一行 `chat`，时间是第一条消息的时间。

### 3. 雇主这边

- 「申请人」页改名「聊过这个职位的人」，链接、计数照旧。chat 行的卡片显示名字、「X 开始聊」、「没有发主页，资料在聊天里问」，按钮是「打开聊天」；合适 / 不合适 / 已录用、约面试跟申请一样。
- 聊天的职位条下面（雇主一侧、双方共享的对话）加「合适」「已录用」两个按钮（`aria-pressed`），再点一次取消，旁边链到这个职位聊过的人。不合适只在列表里标。演示对话和演示候选人没有这两个按钮。
- 职位数据的漏斗第一步从「申请」改成「聊过」，数全部行。

### 4. 求职者这边

- 「我的申请」也列 chat 行，状态写「聊过」（标了合适是「雇主觉得合适」，已录用、职位结束照旧；不合适照旧不显示），日期写「X 开始聊」，没有附言。原因：面试邀约只能在「我的申请」里回，「已录用 / 招满 / 已结束」和面试通知点开也都到「我的申请」；只列申请的话，在聊天里约的面试求职者回不了。
- 职位行上的「已申请」只认申请。
- 导出（`account-data.ts`）带上 `source`；删号照旧把这些行连同面试一起删。

### 5. 测试

- 删掉只给浏览器测试造申请的 `POST /api/dev/apply`、`applyForTest`，以及 `applyForJob`、`withdrawMyApplication`、`myJobApplication`、`withdrawApplication`。单测里旧的申请用 `addApplication` 直接造（代表 10-20 以前的申请）；浏览器测试从职位页的「立即沟通」开始，发一条消息。

## 待用户

- **总览待办和职位卡只数新申请**：chat 行不算「新」，有人来聊靠聊天的未读提示。要不要把「新来聊的人」也算进待办，用户可改。
- 已有的申请记录（10-20 以前的）照旧在雇主列表里带主页和附言显示。
- 「我的申请」的标题没改：现在里面也有只聊过的职位，可以改成「申请和沟通」之类，用户定（A 的 #354 也在改这一块的说明）。

## 后果

- 申请表的名字（`job_applications`、`applied_at`）还叫「申请」，代码注释写明它是候选人表；不改名，省一次大迁移。
- 以后再有「一个职位的候选人」的新来源（例如雇主从推荐人才里直接标），可以加一个 `source` 值，不用改表。
