# 0024 服务器没回答时：读取在原处说没取到、可以重试，操作在按下的地方说明，不交给出错页

- 状态：已采纳
- 日期：2026-10-19（雇主端 #246–#248，求职端 #250–#254）。补充 ADR 0017（求职者主页存在账号上）、ADR 0022（企业主页存到服务器）

## 情况

页面的数据和按钮几乎都走 Server Function。网断了、服务器在重启时，调用拿不到回答（promise 被拒绝），以前各处的处理是这几种：

- **读取只写了 `.then`。** 职位管理、申请人、团队、企业验证、总览、简历的分享卡片等，一直停在骨架屏上，用户只能自己刷新。
- **操作在 transition 里抛出。** 错误交给 `[lang]/error.tsx`，整页换成通用出错页，表单里填的、选的都丢了（企业验证的联系人和电话、发布页粘贴的招聘消息、问题框里选的招到人数）。
- **先改了样子，失败也不改回。** 退出登录先清掉本地的登录副本，服务器上的登录其实还在。在公用电脑上，这等于以为退出了，其实没有。
- **把没回答当成没有。** 通知里的提醒职位没取到，就显示「暂无通知」；总览里面试待办没取到，就显示「都处理完了」。

审核后台在 #183 已经做过一套（`admin/load-state.ts`、`use-admin-load.ts`、`Failed.tsx`）。这一轮雇主端、求职端都要做，统一成一套共用的。

## 决定

1. **共用的部件放在 `src/components/ui/`，两端都用。**
   - `server-load.ts` 的 `shownLoad(got, key, version)`：纯函数，有单测，决定现在显示什么。
   - `use-server-load.ts` 的 `useServerLoad(key, load)`：返回 `{ value, failed, reload }`。
   - `LoadFailed.tsx`：没取到的卡片。
   - ui 字典的 `load`：`notLoaded`、`retry`、`noAnswer`。
   - 审核后台保留自己那套，因为它还要处理「拒绝」（refused）和 `settle`。以后要合并，另开一项。
2. **读取按 key 和 version 判断（`shownLoad`）。** key 是「谁的、哪一个」，比如账号加职位 id；version 每重读一次加一。
   - `key` 是 undefined 时（还没登录、没有账号）不读取。
   - 已经读到的答案，在下一次重读的路上继续显示，改动之后列表不会闪回骨架。
   - 失败只对失败的那一次（它的 version）算数。按「重试」后 version 加一，马上回到骨架等新的回答，不会一直挂着旧的失败。
   - 换了 key（换身份、换账号、换职位），旧的答案和旧的失败都不显示。不按 key 记的布尔失败状态会挡住新身份的列表（B 审查 A 的 #254 时发现过），所以失败要和 key 一起记。
   - 自己管列表的地方（申请人、职位数据的列表会就地改；收藏、提醒、申请记录页）可以不用这个 hook，但要照同一条规矩：失败按 key 记，重试时清掉。
3. **没取到时说什么、放在哪里。**
   - **LoadFailed**：在列表或卡片的位置写「<what>没取到，可能是网络断了。」，旁边是「重试」，`role="alert"`。`what` 由页面自己给，比如「职位」「团队」「面试待办」，英文是 "your jobs" 这类。用在本来只有骨架、自己没有出错文字的地方。
   - **RetryLine**（`components/seeker/RetryLine.tsx`）：保留那个地方原来的出错文字，旁边加「重试」。用在已经有自己说法的地方：收藏、提醒、申请记录、联系方式。
   - **页面其余部分照常显示。** 总览里面试待办没取到，别的待办照样列出，但不写「都处理完了」；通知里提醒职位没取到，不写「暂无通知」。没回答不能当成「没有」。
   - **没回答和服务器拒绝分开说。** 比如联系方式：没回答是「网络有问题，联系方式没取到。」加重试；服务器不给，照旧是「暂时无法获取…」。
4. **操作没回答：在按下的地方说明，不交给出错页。**
   - 每个 Server Function 调用都接住拒绝（`.catch(() => null)` 或 try/catch），在按下的那张卡片、表单或出错行里说「网络有问题，请稍后再试。」（`load.noAnswer`），或者那个地方自己的说法，比如简历分享卡片的「分享链接没有改成」。
   - 填的、选的都留着：表单不清空，问题框不关，粘贴的消息不丢。团队邀请等发出去以后才清空邮箱。
   - 按钮在等回答时是 `loading`（`aria-disabled`，不是 `disabled`，焦点留在按钮上，#202）。失败以后照样能按，再按一次就重试。
   - **不顺手重读。** 操作没回答时，列表也读不到，重读会让「没取到」把还开着的问题框换掉。职位管理用 `NoAnswer` 这种结果区分：只说明，不 `reload`。
   - **先改样子的操作，等服务器回答了再改。** 退出登录要等服务器回话了才清本地；没回答就留在原页，用 toast 说「还没有退出登录，请再试一次」（#254）。
   - 出错文字出现在页顶、按下的按钮在页底时，出错行要拿焦点（`useFocusOnChange`，#248）。
5. **恢复联网后：有 online 事件的地方自动重读，但一定要有「重试」。**
   - 收藏、已申请的 id 是全站共用的 store（`saved-client.ts`、`applied-client.ts`）。读不到时挂一个 `online` 监听，用同一个函数，同一个监听只会挂一次；`ids || loading` 挡住重复请求。已申请的 id 和通知里的提醒职位只认最后一次请求的回答，先发的那次后回来，不会盖掉新的。
   - 账号上的主页比较（`profile-client.ts` 的 `compare`）：失败时记成 `offline`（有改动没送出）或 `unreached`（没有改动，但显示的不一定是账号上那份），按身份只挂一个 `online` 监听。拿到回答时先把状态清回 idle，再走后面的步骤，「没连上」不会一直留着。
   - 聊天的发件箱（#10）本来就会一直重发；#253 起在消息上标「未送出」，顶部写还有几项没送到，旁边有「重试」。
   - **服务器重启时浏览器一直在线，不会有 online 事件**，所以每个「没连上」都要有人能按的「重试」，不能只等 online。`useServerLoad` 本身不监听 online，靠「重试」和下一次挂载组件。
6. **测试的做法。** e2e 只拦本页路径的 Server Function POST（`route.abort("internetdisconnected")`），页面和脚本照常加载。每一处都要验：
   - 说了什么，提示用 alert 加文字过滤，不要整页 `getByRole("alert")`；
   - 填的还在；
   - 按钮还能按；
   - axe 通过；
   - 恢复联网后同样再按一次，这次成功了，提示也消失了。

   雇主端在 `e2e/employer/errors.spec.ts`，求职端在 `e2e/seeker-errors.spec.ts`，审核后台在 `e2e/admin-errors.spec.ts`。`route.abort` 不会触发 online 事件，靠 online 重读的那条路要用 `context.setOffline(true/false)` 测，留到跑门槛时补。

## 故意不做的

- **切换身份、通知已读失败后不改回**（#254 收窄范围）。本地已经切了或标了已读，服务器没收到的话，下次打开页面会重新发一次，两边就对上了；改回去反而让人以为没按到。收藏页的进度下拉，保存失败时本来就会回到原值，不用改。
- **企业资料（`useEmployerProfile`）没取到时，雇主各页不显示卡片**，用登录时存下的那份（店名、验证状态）接着显示，和读取途中一样。真要用到它的地方（总览的雇主那一半）自己用 `failed`，A 在 B 的 #246 合并后补。
- **「我的」里的团队邀请卡片没取到就不显示**，和没有邀请一样，「我的」其余部分照常。
- **雇主的「发起聊天」**（申请人、推荐人才）没回答时，按钮回到原样，雇主这边不另加文字；求职端 #253 的 `openOnServer` 会弹一个 toast，两边都有说明。
- **不自动反复重试、不做退避。** 一次没回答就说明，由人按「重试」，或者等 online 事件。这样不会在服务器重启时一直打它，页面上也看得出发生了什么。
- **不新开离线模式。** 读不到的数据不从本地拼出来充数（主页的本机副本照 ADR 0017 显示，但标明「没连上」）。

## 后果

- 断网或服务器重启时，任何一页都不会一直转圈，也不会整页换成出错页。填的东西留着，恢复以后再按一次就行。
- 新页面照这套做：读取用 `useServerLoad` 加 `LoadFailed`，或者 RetryLine；Server Function 调用都接住拒绝；e2e 加一条断网再恢复的测试。代码审查时，看到不接拒绝的 `.then`、没有 catch 的 `await action()`，就照这里改。
- 两套并存：审核后台的 `load-state.ts` 和共用的 `server-load.ts`，做法一样，代码两份。
- 总览的雇主那一半、推荐人才里账号上的人选没取到时的说明，等 B 的 #246 和 A 的 #250 合并后各自补上。
