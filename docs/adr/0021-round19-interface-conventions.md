# 0021 Round 19 的界面约定：卡片、整张卡的链接、共用的 Select 和骨架屏

- 状态：已采纳
- 日期：2026-10-18（#168；做法来自 #140、#141、#152–#154、#160、#161，用户 10-17 19:3x 看过样板）

## 情况

Round 19「操作质感」要让网站用起来像 App：按下有反馈，页面不闪白，手机上的选择从底部弹出。三条线同时在改几十个页面。做法要是只写在各个 PR 里，每条线会各写一套：有的用细线分隔，有的用卡片；有的在卡里放链接，有的把按钮挂在卡外（#160 就是这样来的）；有的用原生 `<select>`，有的用共用的 `Select`。

## 决定

1. **页面的块是卡片，不是细线。** 白底、16 px 圆角、柔和阴影、没有边框（`cardClass()`、`Card`、`Section look="app"`），卡与卡之间 12 px。列表里的一行一行用 `rowClass()` / `LinkList`，按下整行变暗。页面最外层加 `type-app`（正文 15 px，灰字加深，桌面大一档）。
2. **整张卡打开一个地方时，只有一个链接，盖满整张卡。** 标题里的链接用 `after:absolute after:inset-0` 撑满卡片（`linkCardClass()`），读屏只念标题。卡里还要放按钮（收藏、申请、立即沟通）时，按钮用 `relative z-10` 浮在链接上面，放在卡片底部那一行；不把按钮挂在卡外（#160，`JobCard` 的 `action`）。整张卡就是一个链接、里面什么都不放时，用 `CardLink`。
3. **下拉一律用共用的 `Select`**，不写原生 `<select>`：手机上是底部弹层，768 px 起是下拉，可以用键盘选；JavaScript 跑起来之前和没有 JavaScript 时，它是原生下拉框，表单照样能提交。受控（`value`）、`hideLabel`、`tone` 这些变体在 #152 里。e2e 用 `chooseOption()` 选，用 `selectTrigger()` 的名字读当前的值。
4. **页面不闪白。** 按请求取数据的路由要有 `loading.tsx`，骨架照内容的样子画（`Skeleton`、`SkeletonList`、`ListPageSkeleton`、`DetailPageSkeleton`）。不在根目录放 `loading.tsx`，因为它会成为所有子路由的占位；首页这类外壳已经预渲染的页面，只给按请求的那几块换骨架占位（#167）。骨架带 `data-nojs-hide`，没有 JavaScript 时藏起来。
5. **找不到和出错时显示同一张卡**（`StatusCard`）：图标、标题、一句原因、一个主按钮。全站的 `not-found.tsx`、`error.tsx`、`global-error.tsx`，以及职位、雇主的 404 都用它（#161）。
6. **共用组件 `src/components/ui` 只由 A 线改。** 别的线需要新变体时在队列里提，A 线加好后各线再用；各线自己目录里的样式（比如雇主后台的 `app-style.ts`）只放共用组件管不到的东西。

## 放弃的做法

- **整张卡用 `<a>` 包起来，里面再放按钮：** 链接里套按钮不合 HTML 规定，读屏会把整张卡的文字连着念一遍。
- **把卡里的按钮挪到卡外（#153 雇主主页原来的样子）：** 按钮悬在两张卡之间，看不出属于哪张。
- **只让标题可点：** 用户点头的样板是整张卡可点（按下整张卡缩一点），手机上点得到的面积也大得多。
- **各页面自己写下拉弹层：** 键盘、读屏、没有 JavaScript 时的退路都要每处重做一遍。

## 后果

- 新页面照这几条写，审 PR 时对照本篇和 `docs/design-system.md` 的 Round 19 一节。
- 卡里浮在链接上面的按钮要自己记得加 `relative z-10`，不然点到的是链接。`linkCardClass()` 的注释写了这一条。
- `Select` 在 JavaScript 加载前是原生下拉框，第一次渲染和加载后长得不一样；e2e 要等它换好再操作：`chooseOption()` 按「按钮」去找触发器，原生下拉框不是按钮，所以会自动等到换好。
