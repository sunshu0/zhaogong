# 0043 审核员账号只做审核；管理员来自服务器配置，只有管理员能增删审核员

- 状态：已采纳（导师 local_573a9208 裁定，说明 `zg-scratch/mentor-573a/brief-A-06.md`；执行 A local_b3d9b61a 起草）
- 日期：2026-10-26。Issue #398。用户 10-26 19:5x：「审核员现在的布局太杂了 审核员只需要有审核员需要的功能 把其他的都删了 保留和雇主和审核员聊天」，选项卡选「审核员账号专用」；20:0x 选「设一个「管理员」身份」（起因：「审核员可以随意添加或者删除审核员 这样设计也有风险」）。

## 情况

审核员就是普通账号加一行 `moderators`：登录后先选求职者还是雇主，顶栏、底部导航、「我的」全是找工作、招聘的东西，审核后台只是账号菜单里的一项。审核后台一页堆了九个标签（标记、举报、聊天风险、企业验证、外部职位、操作记录、查看记录、审核数据、审核员），哪些等着处理、哪些只是看看，分不出来。任何审核员都能增删审核员，最后一个不能删。

## 决定

### 1. 谁是「工作人员」：服务器判断，随会话告诉浏览器

- 管理员：服务器配置 `ZHAOGONG_ADMIN_EMAILS`（逗号分隔，`src/db/admins.ts`）里的邮箱。网页上改不了；部署时用户在 Cloudflare 设变量。本地演示 `.env.development` 和测试服务器（`scripts/e2e-server.mjs`）设成 `admin@example.com`，种子数据给它建账号。
- 审核员：`moderators` 里的一行，跟以前一样。管理员也算审核员（`isModerator`、`requireModerator` 都认），能用审核后台的全部功能。
- 只有 `ADMIN_ENABLED=1` 时才算数（审核后台关着时，审核员账号就是普通账号，不会被送去一个 404）。
- 登录、核对会话、切换身份的回答（`login/actions.ts` 的 `withStaff`）带上 `staff: "admin" | "moderator"`，每次都查数据库，所以撤销审核员后，下一次页面加载就变回普通账号。浏览器把它记在会话副本里（`DemoSession.staff`），界面按它显示。以前账号菜单每次打开问一次的 `canModerate()`（#73）就不要了，同一件事并进了会话。

### 2. 工作人员的界面只有审核后台

- 登录后不选身份，直接进 `/admin`（`next` 是公开页的话去那里）；`/login` 上不出现「开通雇主身份」。
- 顶栏只有「审核后台」和账号菜单（菜单里是身份、审核后台、退出登录）；不显示职位搜索、发布招聘；手机底部导航是「审核后台」「我的」两项（在 `/admin` 上也显示，那是他们的首页）；页脚不列求职者和雇主的链接。
- 「我的」（`/account`）只有身份（管理员或审核员，加一句「这个账号只用来审核」）、审核后台、语言、退出登录。
- 打开别的页面（首页、职位、我的申请、发布招聘、数据与账号……）会被换成 `/admin`（`StaffRedirect`，`replace`，返回键不回去）。关于、防骗指南、隐私、条款、登录照旧能看（`staffMayOpen`）。
- 服务器上，工作人员不能开通雇主身份（`openEmployerForAccount` 拒绝）。
- 这是界面上的限制，不是权限：工作人员账号直接调求职者、雇主的服务器动作，动的也只是自己账号的数据，所以不另外挡。

### 3. 审核员只给干净的邮箱

- 授予审核员（审核后台和命令行一样）时，邮箱要已经注册过，而且没有求职者或雇主的数据：资料和简历（`seeker_profiles`）、简历分享、投递、收藏（含外部职位）、职位提醒、雇主身份或团队（`accounts.employer_id`）。有就拒绝，提示「请用一个专门的审核员邮箱」。判断写在授予的同一批语句的条件里（ADR 0031），中间插不进别的写入。
- 已经是审核员、又有这些数据的账号：不删，只是界面上看不到（第 2 条）；撤销后原样回来。演示审核员 `moderator@example.com` 本来就没有这些数据。
- 管理员的邮箱是配置定的，不检查；部署前用户应当用专门的邮箱。

### 4. 只有管理员能增删审核员

- 审核后台「审核员」一页：管理员看到名单（管理员标出来，写「在服务器配置里设定」）、添加和移除；普通审核员只看到名单和一句「只有管理员能添加、移除审核员」。
- 服务器动作 `addModerator`、`removeModerator` 先查是不是管理员（`actingAdmin`），不只是藏按钮。
- 网页上移除不了管理员（它不在表里，在配置里）。
- 命令行 `npm run admin:grant` / `admin:revoke` 照旧能用（能登服务器的就是用户本人）。

### 5. 每次增删都留记录

- 新表 `moderator_changes`（迁移 0038）：时间、加还是删、对谁、谁做的（管理员的邮箱；命令行是空，显示「命令行」）。和 `moderators` 的那一行在同一批语句里写，要么都成，要么都不成。首位审核员的 SQL 文件（`moderator-sql.ts`）也写一条，重复导入不重复写。
- 只有管理员能看：审核后台「记录与统计」里的「审核员变动记录」，服务器动作 `getModeratorChanges` 也只回答管理员。
- 删除账号时，记录里的这个邮箱换成 deleted-account（和 `moderation_log` 一样），记录本身留着；「导出我的数据」带上和这个账号有关的几条（自己的审核员身份给了、去了，作为管理员给别人加、删的）。

### 6. 「最后一个审核员不能删」去掉

管理员来自配置，永远在，能审核也能再加审核员，所以审核员可以删到零。删除账号时的「最后一位审核员不能删账号」（ADR 0009 那条）不动：工作人员账号进不了「数据与账号」，那条现在走不到，以后再看。

### 7. 隐私页不改

这张表记的是工作人员（审核员、管理员）在工作中的操作：谁在什么时候给谁加了、去掉了审核权限。它不是找工用户的求职、招聘数据，不给别的用户看（和这个账号有关的几条进它自己的导出，跟审核员的处理记录一样）；和已有的 `moderation_log`（审核员的处理记录）同一类：隐私页「删除」那条说的「审核记录……把你的邮箱换成「已删除的账号」」已经包括它，这里正是这样做的。审核员的邮箱是他们为了做这份工作给平台的，用途就是审核和问责，没有新用途。所以不改隐私页。（拿不准的地方见汇报：要不要在隐私页的「工作人员」一节统一写一句，由导师判断。）

### 8. 审核后台分两组

- 「待处理」：发布时被标记、被举报、聊天风险、企业验证、外部职位，每项带数字；组的入口上是加起来的总数；上面是「现在等着的」那四个数字（`ModerationSummary`）。
- 「记录与统计」：操作记录、审核数据、查看记录、审核员，管理员还有审核员变动记录。
- 组用圆角标签（控件，`pillTab`），组里用下划线标签；默认打开「待处理 · 发布时被标记」。功能一个没删，只是分组。
- 换新样式（ADR 0036）：点了不去别处的块都是纸（`Section look="sheet"`、`sheetClass()`，细线，没有阴影）；每一条都有的「通过」改成次按钮，一屏最多一个主按钮。`Section look="app"` 没人用了，删掉这个变体，视觉 A 收尾。

## 不做

- 审核员和雇主聊天（等 B 的手机聊天整屏合并后另派）。
- 不删任何账号数据，不改审核、核实、举报证据、查看记录这些动作的规则。

## 后果

- 新部署要设 `ZHAOGONG_ADMIN_EMAILS` 才有人能在网页上增删审核员；不设的话只能用命令行。`docs/cloudflare-deployment.md` 的变量表写了。
- 测试里给别的账号加审核员，要用管理员（`admin@example.com`）的会话。
