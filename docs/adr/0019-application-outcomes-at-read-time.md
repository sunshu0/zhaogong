# 0019 已录用和职位结束：录用存在申请上，「职位已结束」在读取时算

- 状态：已采纳
- 日期：2026-10-17（#105，R-35、R-31）

## 情况

雇主结束职位时会问招到几个人（B14），但申请人什么都收不到，一直停在「已申请」或「雇主已看过」。#105 要做三件事：雇主能把申请人标为「已录用」；职位结束（招满、雇主结束、到期、被下架）时，没被录用的申请人收到一条礼貌的通知，状态改成「职位已结束」；求职者的「我的申请」分「进行中」和「已结束」。

职位结束有好几种来路：雇主点「结束招聘」（`status = expired`，`expires_at` 改成当时）、过了截止时间（状态还是 `active`，读取时才算截止，ADR 0008）、审核员下架或封禁企业（`removed`）、删除账号时下架。

## 决定

1. **「已录用」是申请的第三种决定。** `job_applications.decision` 原来是 `fit` / `unfit`，加上 `hired`，录用时间用已有的 `decided_at`。它和「合适 / 不合适」互斥：录用了就不再是「合适」。不用迁移（这一列是文本）。
2. **「职位已结束」不存，读取时按职位算**（`jobEndedAt`）：`expired` 或过了截止时间，结束时间是 `expires_at`；`removed` 的时间从审核记录里找（这个职位的下架，或者它的企业被封禁），找不到时用截止时间和现在里早的那个；待审核的不算结束。和 ADR 0008 一样，这样不需要在职位结束的那一刻去改每份申请，也不会因为「到期」没有人触发而漏掉。
3. **通知也在读取时生成**（`src/app/me/application-notifications.ts`，由 `serverNotifications` 汇总）：
   - 被录用的人：「〈店名〉录用了你」，编号 `hired:<申请编号>`，雇主标了就有，不等职位结束。
   - 其余申请人，在职位结束后：「〈职位〉已经招满」（雇主结束时说招到了人）或「〈职位〉已结束」，编号 `job-ended:<申请编号>`。
   - 编号固定，所以读过一次就一直是已读（`markMyNotificationsRead` 只接受 `serverNotifications` 给出的编号）。
4. **「不合适」的人收到和别人一样的通知、看到一样的状态。** Issue 原文写「没被录用、也没被标不合适的」收到通知。如果只有标了「不合适」的人收不到，求职者对比一下就知道自己被标了「不合适」，这违反 R-35「标不合适时求职者只看到雇主已看过」。所以职位结束后，所有没被录用的人都看到「职位已结束」，措辞里不出现「拒绝」「不合适」。
5. **「我的申请」分组：** 被录用或职位已结束的放进「已结束」，其余是「进行中」。已结束的不能撤回，也不再显示面试邀约的操作，只留记录。
6. **职位数据加「申请到录用」：** 申请人数、约过面试的人数（不算已取消的）、录用人数，从发布到现在，每次请求时从 `job_applications` 和 `interviews` 数。

## 后果

- 结束职位、职位到期都不需要后台任务，也不会因为服务器在那一刻没运行而漏发通知。
- 每次打开通知都要读这个账号的全部申请和对应的职位；一个人的申请不多，现在没问题。下架的职位要读整张审核记录（ADR 0010 说了数据多了以后怎么办）。
- 通知的时间是「今天」「N 天前」，按结束时间算，不是按发出时间。
- 通知只在站内；邮件提醒等邮件服务（#16）。
- 雇主取消「已录用」时，那条「录用了你」的通知会消失，职位结束后换成「职位已结束」。
