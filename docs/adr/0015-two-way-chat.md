# 0015 双方聊天：一条对话双方共用，演示内容只给演示账号

- 状态：已采纳（两部分都已做）
- 日期：2026-10-17（#110，PRD R-20、R-21）。补充 ADR 0012（聊天按企业共享）和 ADR 0009（删除账号）

## 情况

到 #87 为止，求职者和雇主之间的聊天没有真正连起来：每个身份（雇主是每家企业）只有自己的一份记录（`chat_records` / `team_chats` 里的 `ChatRecord`），对方的回复来自演示脚本或开发用的 `/api/dev/chat-reply`。一方发的消息，另一方永远收不到。`conversations`、`messages`、`exchanges` 三张表从 A12-2 起就预留着，一直没人写。

另外，演示内容给了所有人：一个刚注册的雇主在通知里就有「林晓回复了你的面试邀请」，聊天里有 4 条未读（导师验收 #78 时发现）。真实账号不该看到编出来的人和事。

## 决定

### 第一部分：演示内容只给演示账号

- **演示账号**（`src/lib/demo-accounts.ts` 的 `isDemoAccount`）：`seeker@example.com`、`boss@example.com`、`moderator@example.com`，以及以 `demo.` 开头的 `@example.com` 地址。后一种是给浏览器测试的：每个测试用自己的演示账号，并行的测试不共用一份演示记录。example.com 收不到邮件（RFC 2606），真实网站上没人能用这些地址登录。
- **演示聊天**（`chatDemo(isEmployer, demoAccount)`）和**演示通知**（`initialNotifications`）只给演示账号；其他账号从空白开始。浏览器、服务器、「收藏和进度」都按账号判断。团队里的人看演示对话也按自己的账号判断。
- 聊天页和通知页加空白时的说明（「还没有聊天。在职位详情里点「立即沟通」……」）。聊天页的「演示数据」标记和底部说明只在演示账号上显示。
- #110 之前的浏览器数据（还没分版本的）仍按完整的演示来解析，只用来分出用户自己的部分。

### 第二部分：双方共用对话

- **一条对话 = 求职者账号 + 企业 + 职位。** 存进 `conversations`（`seeker_email`、`employer_id`、`job_id` 唯一）。求职者从职位「立即沟通」和雇主从申请人「发起聊天」进的是同一条。迁移 0017 给 `conversations` 补 `seeker_name`、`seeker_read_at`、`employer_read_at`、`updated_at`，给 `messages` 补 `by_name`（企业一方发送时的称呼，ADR 0012）。没有 SQL `DEFAULT`（ADR 0005）。
- **浏览器的形状不变。** 服务器把这个身份能看到的共用对话拼进它的 `ChatRecord`（对话、消息、双方已读、交换），浏览器的缓存、`chat-outbox` 和页面组件照旧。`changeMyChat` 遇到共用对话就写表；演示对话、和演示候选人的对话、举报照旧写各自的记录（举报的证据可以取自共用对话）。防重复的改动编号仍按人记。
- **编号：** 求职者那边是 `employer:<企业>:<职位>`（和以前一样，一个求职者对一个职位只有一条）；雇主那边是 `chat:<对话编号>`，雇主「发起聊天」等服务器回答（`ChatSnapshot.opened`）后再进对话，按钮在等的时候不能再点。
- **对方什么时候看到：** 一方打开对话还没说话时，对方的列表里没有它；有了第一条消息或交换请求才出现。
- **已读：** 每条对话记双方各自最后读到的时间；对方的消息早于这个时间就算读过，自己的消息早于对方的时间就显示「已读」。团队里任何一个人读过，就算企业读过。
- **交换资料**用 `exchanges` 表，双方看到同一条；R-12 的规则（发起方先给自己的，对方同意才给回）不变。
- **新消息怎么到：** 没有推送。聊天页在前台时每 10 秒、回到页面时重新读一次。WebSocket 或 Durable Objects 等部署方式定了再说。
- **推荐人才：** #104 之后推荐人才来自账号上的主页（`local-<candidateId>`），服务器按 `resume.candidateId` 找到这个账号，对话和申请人的一样是双方共用的。雇主看到的名字是对方主页上现在的名字；对方关掉「允许向雇主推荐」后，对话还在，只是不再链到他的主页。演示候选人（林晓等）不是账号，和他们的对话仍记在企业自己的记录里。
- **旧记录不搬。** #110 之前求职者发给企业的消息只在自己这一侧，雇主从来没收到；它们留在自己的记录里，照样能看，新消息走共用对话。
- **删除账号（补充 ADR 0009）：** 求职者删号时，他的共用对话连同消息、交换一起删（以前就按 `seeker_email` 删）。企业最后一个人删号时，这家企业的共用对话也一起删（双方的消息都删，和 `team_chats` 一样）；团队里还有人时都留着，删号的人发过的消息仍署他在团队里的称呼。导出数据里有求职者自己的共用对话（双方的消息和交换）；雇主一方写的属于企业的聊天，和 ADR 0012 一样不放进个人导出。

## 后果

- 真实账号之间第一次能真正对话；演示账号的演示对话和自动回复保留，只在演示账号上出现，并标明「演示数据」。
- 浏览器测试里依赖演示对话的测试改用 `demo.` 开头的地址；其余测试用普通地址，测的就是真实账号看到的样子。
- 新消息在聊天页上最多晚 10 秒出现；页面不在前台时不读。别的页面（底部栏的未读数）只在打开页面时读一次。
- 新求职者的「我的主页」默认还是演示人物林晓的资料（`initialProfile`），不在这一项里改，留给 #104 之后单独的一项。
