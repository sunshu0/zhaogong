# 0049 主要操作的交互延迟预算：单独测量，超时只提示

- 状态：已采纳；实现和首次数字须以实际门槛记录验收。
- 日期：2026-10-28。Issue #418。
- 授权：用户 10-27 01:24「操作手感就先按你的方案执行」；总导师 10-28 03:1x 的 R2 已允许现在增加独立 inp 门槛段，覆盖原任务卡“暂不进门槛”。

## 情况

首屏 JavaScript 预算只能发现下载变重。返回列表、聊天与底部弹层的操作手感还需要可重复的实验室数据。这里测五项固定操作，不收集真实用户的浏览数据。

## 决定

1. 使用 Chromium、375×812 CSS px、触摸、CPU 4× 节流。职位卡、详情「立即沟通」、聊天发送、「更多」、筛选弹层，各执行五次，报告中位数、最差和 200 ms 参考线。`INP_RUNS` 可用于临时诊断，必须为正十进制整数；正式门槛不覆盖默认五次。
2. 固定使用 `npm run e2e:build` 产生的 `.next-e2e` 生产测试构建。配置只启动 `scripts/e2e-server.mjs start`，不启动开发服务器、不复用已有服务；端口被占用、构建缺失或显式指定非 start 模式均失败。普通 `e1–e8` 的目录和 `npm run check` 不包含本次浏览器测量。
3. 用原生 Event Timing（`PerformanceObserver` 的 `event`、`durationThreshold:16`），不增加依赖。页面初始化时安装采集器，按目标上可信 `pointerdown` / `pointerup` / `click` 的时间戳匹配记录，再按 `interactionId` 归组，取该次交互最长的 duration。完整原始记录和窗口存进 `test-results/inp.json`，无关事件不计入目标样本。
4. 这叫**固定操作的交互延迟**，不是整页真实用户 INP。web-vitals 的 `onINP` 还涉及页面生命周期与交互数量的候选选择；本实验没有声称实现那个整页算法。Event Timing 包含输入等待、同步事件处理到下一次绘制，**不等于异步请求到最终内容完成的总时间**。测试另等预期页面/消息/弹层出现，只用于确认该操作确实成功。
5. 采集能力和链路必须验证：目标前后各有一次仅由测试注入的可信校准点击，处理器故意忙等 48 ms，以确认同一文档的观察器能交付慢事件；校准不计入目标窗口或样本。开着原生模态弹层时，校准按钮放在弹层内部，避免背景 inert 无法点击。能力缺失、校准失败、目标事件不全或不可信、多个 interactionId、原始证据不一致均失败。
6. Event Timing 最小阈值是 16 ms，浏览器还会对 duration 作时间精度舍入。只有前后校准均成功、目标可信事件完整、文档未变化时，没有匹配条目才标为 `below-threshold`，以 16 ms 作为报告上界；JSON 保留这个状态，控制台明确打印数量。不能把“不支持 / 采集坏了”当成很快。硬导航替换文档导致旧记录不可读时明确失败，不能补成 16；React 标记只做准备检查，预期结果与文档身份另外检查。
7. 报告要有五项唯一操作，每项样本和原始测量数都等于请求次数，数字有限且非负，并验证 CPU、视口、构建模式和校准证据。缺项、坏 JSON、异常进程或点不成退出非零；有完整有效样本但超过 200 ms 仍退出 0、只提示，不阻止合并。

## 门槛与资源（R2）

- 在 e8 后单独安排 inp 段，不塞进现有 e1–e8。独立拿共用 GPU 锁，一段最多 15 分钟；开跑空闲内存至少 3.5 GB，间隔至少 30 秒读两次，owner 的 command 写明 inp。
- 前三次记录实际时长、包含浏览器和服务器的进程树峰值内存，以及同时在跑的其他活动。超过 10 分钟或峰值超过 1.5 GB 时报总导师，三次后回填 R2。
- 数字目前只提示。是否升级成阻止合并的性能阈值，留给后续观察和明确决定。
- 实际门槛集成由找工导师在本任务的隔离脚本副本中安排；不直接改工程化组工具。

## 限制与后续

这次不修产品性能、不测桌面或加载指标；CPU 4× 只是固定实验条件，不代表某款真机。校准会增加总执行时间，其点击也可能干扰焦点和手机键盘：测试保存原焦点、移除校准按钮后恢复，并在目标开始前等待绘制稳定；真实手机键盘行为仍需真机验证。校准的慢处理和绘制不计进被测目标。首次实测、命令花费与并发情况只据运行日志填写，不预填通过数字。复跑应绑定同一代码树、浏览器版本、生产测试构建与资源条件。
