# 0012 雇主多人管理：一家企业一个团队，管理员和成员

- 状态：已采纳
- 日期：2026-10-17（#87，PRD R-38）。补充 ADR 0003（一个账号两种身份）和 ADR 0009（删除账号）

## 情况

到 #86 为止，一家企业只能绑一个账号（`accounts.employer_id` 唯一）。真实的小店常常是老板和店长、前厅经理一起招人：老板发职位，店长回求职者的消息。共用一个邮箱登录会让验证码、会话和「谁说了什么」都说不清。

同时，聊天记录按「邮箱 + 身份 + 企业」各存一份（#10，`chat_records`）。如果一家店有几个人，每个人只能看到自己那一份，团队里的人互相看不到对方回了求职者什么。

另外要说明：求职者和雇主之间的聊天现在还没有真正连起来——每个身份的记录只有自己这一侧，对方的回复是演示内容或开发用的 `/api/dev/chat-reply`。真正的双方聊天是 #110。所以这一项只做雇主这一侧。

## 决定

- **账号仍然只属于一家企业，一家企业可以有多个账号。** `accounts.employer_id` 保留，只去掉唯一索引（`DROP INDEX`，不重建表）；加三个可空列：`team_role`（`admin` / `member`）、`team_name`（团队里的称呼，如「王经理」）、`team_joined_at`。迁移 0013 把已经绑了企业的账号设为管理员，加入时间取账号创建时间。没用 SQL `DEFAULT`（ADR 0005）。
- **开店的人是管理员；之后只能被邀请加入。** `openEmployerIdentity` 在企业还没有人时把开店的账号设为管理员；企业已经有人时返回 `taken`，页面提示找这家店的管理员邀请。
- **邀请：** 新表 `team_invites`。管理员按邮箱邀请，对方要先登录过找工（账号存在），并且还没有企业；同一家企业对同一个人只能有一条没回复的邀请；团队（包括没回复的邀请）最多 10 人。被邀请的人在「通知」和「我的」里看到邀请，填上称呼后接受，或者婉拒；管理员可以撤回没回复的邀请。接受后服务器把会话切到雇主身份。
- **权限：** 成员能发职位、管理职位、处理申请、回复聊天；只有管理员能申请企业验证（#78）、管理团队（邀请、撤回、改身份、移出）和改企业主页（ADR 0022，补充）。规则写在 `src/components/employer/team.ts`（纯函数，有单测），每个改动在写入的同一个事务里再检查一次（`src/db/team.ts`）。页面只是跟着显示。
- **团队里永远至少有一位管理员。** 最后一位管理员不能改成成员、不能被移出、不能自己退出，也不能删除账号（要先把别人设为管理员），和「最后一位审核员不能删除账号」同理。
- **聊天记录按企业存一份。** 雇主身份的聊天记录存在新表 `team_chats`（每家企业一行），团队里的人看到同一批对话；通知已读和防重复的改动编号仍按人存在 `chat_records`。浏览器的缓存键不变（还是自己的身份）。#87 之前的记录：企业还没有共享记录时，先读当前这个人自己那份，第一次写入后就成为企业的记录。
- **每条雇主一侧的消息记下回复人。** 消息加可选字段 `by`：发送时这个人在团队里的称呼（快照，之后改称呼不影响旧消息）。雇主一侧的气泡上显示这个称呼。#110 做双方聊天时，求职者那一侧显示「店名 · 称呼」（`teamSignature`）。没设称呼的人发的消息没有 `by`，只显示店名。
- **删除账号（补充 ADR 0009）：** 团队里还有别人时，删号只是离开团队：企业的职位、共享聊天都留着。企业最后一个人删号时才按原来的规则下架职位、清空职位上的联系方式，并删掉共享聊天、撤回没回复的邀请。发给这个账号的邀请随账号删除；它发出的邀请留下，邀请人邮箱换成 `deleted-account`。导出数据包括自己在团队里的身份、称呼和收到 / 发出的邀请。

## 后果

- 一家店可以几个人一起招人，看到同一批对话，知道每条回复是谁发的。
- 职位上的联系方式是发布的人填的；成员离开后，他发的职位还留着他的联系方式，要管理员编辑。~~职位没有记录是谁发的（以后需要时加列）。~~ 已做（#182）：`jobs.posted_by_email`（迁移 0023，可空，以前的职位留空），发布时记会话里的账号；职位管理每条写「小李发布」「你发布的」（团队只有自己时不写）「某某发布（已离开团队）」「已删除的账号发布」。只有团队看得到，不在 `Job` 里，公开页没有。删号时改成 `deleted-account`，导出数据列出自己发过的职位。
- 被移出或退出的人保留账号和求职者身份，雇主身份关闭；他的会话下次读取时自动回到求职者身份。
- ~~企业资料（企业主页）现在仍是每个人浏览器里的一份（ADR 0003），还没有服务器上的版本，所以「只有管理员能改企业资料」要等企业主页存到服务器时再加。~~ 已做：企业主页存到服务器，只有管理员能改，成员看到只读（ADR 0022）。
- 真正的双方聊天（#110）完成之前，求职者看不到回复人。
