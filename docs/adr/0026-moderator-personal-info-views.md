# 0026 审核员看过谁的个人信息：交出去之前记一条，不记内容，保留一年

- 状态：已采纳（导师 10-20 03:2x 派的 #336；编号导师 04:0x 登记）
- 日期：2026-10-20。用户 10-20 01:2x 定了「国内同事可以直连正式数据库」，所以新西兰《2020 年隐私法》和《个人信息保护法》都按适用来做（`docs/data-breach.md`、隐私页第 11 节）。

## 情况

1. **审核员会看到别人的个人信息。** 现在审核后台交给审核员的有：企业验证申请里的联系人姓名、职务、公司电话（`verification-actions.ts`）。职位队列（`actions.ts`）以前把整条职位连同联系方式（电话、微信、邮箱）一起发给浏览器，页面上并不显示。外部职位是公司的公开招聘信息；举报的补充说明不带举报人；审核员名单只有审核员自己。求职者资料和聊天目前不进审核后台。
2. **要能事后查清谁看过。** 隐私法 IPP 5 要防止未经授权的访问和使用；发生泄露时要判断影响了谁（第 112–117 条，`docs/data-breach.md` 第 2 步要「保留审核后台的个人信息查看记录」）。《个人信息保护法》第五十一条要「合理确定个人信息处理的操作权限」、防止未经授权的访问，第五十四条要定期做合规审计。审核员之后可能在中国境内访问，查得到记录更要紧。
3. **记录本身也是个人信息**（审核员的邮箱、什么时候在做什么），不能无限期留着：IPP 9、《个人信息保护法》第十九条（保存期限为实现处理目的所必要的最短时间）。

## 决定

### 1. 交出去之前记一条

- 新表 `personal_info_views`（迁移 0027）：时间（到秒）、新西兰日期、审核员邮箱、哪一类、哪条记录的编号。**不记内容**，也不记 IP、浏览器。
- 类别（`src/lib/personal-info-views.ts`）：`verification` 企业验证申请、`contact` 职位联系方式、`profile` 求职者资料、`chat` 聊天。现在只有 `verification` 会记；另外三类先定好名字，以后哪个页面要给审核员看这些，就在它的 Server Function 里按这一类记。
- 在 Server Function **返回之前**调用 `recordViews()`：没记上就不交出去（写库失败时整个调用失败，审核员看到「没取到，重试」）。没登录、不是审核员的请求什么都不交，也不记。
- 同一位审核员 30 分钟内再看同一条只算一次：每做一个决定，列表会重新取一次，不该每次都多一条。

### 2. 不需要的就不交出去

- 职位队列不再把职位的联系方式发给浏览器（`QueueItem.job` 去掉 `contact`）。页面本来就不显示，交出去只会多一份需要记录的东西。检查规则照旧在服务器上用完整的职位跑。
- 企业验证队列只在审核员打开「企业验证」这一页时才取（以前进审核后台就取）。页签上的数字改用「审核数据」里已有的待审核数。这样记下来的是审核员真的打开过的。

### 3. 保留一年

- 记录留 365 天。没有定时任务（ADR 0008）：每个新西兰日的第一条记录顺手删掉一年以前的，跟 `events` 表一样（ADR 0025）。
- 为什么是一年：法律没有给数字。一年够做一次年度合规审计（第五十四条），也够查清投诉和泄露（隐私法第 112 条起要「尽快」通报，判断范围要回看）；再长就超出了用途（IPP 9、第十九条）。把握：中等。以后有了正式的合规审计周期，或主管部门要求更长，再改 `KEEP_DAYS`。

### 4. 查看记录页

- 审核后台新加一个页签「查看记录」：按审核员（全部或一位）、按时间（最近 7 天、30 天、一年）查，新的在前，一次最多 200 条，超出时提示缩短时间或只看一位。
- 只有审核员能看（`requireModerator`）。这一页只列编号和审核员，所以看这一页本身不记。

### 5. 删除账号

- 审核员删除账号时，记录留下，邮箱换成 `deleted-account`（页面上显示「已删除的审核员」），跟操作记录（#60）一样：记录是为了被看的那些人。
- 审核员导出自己的数据时，里面有自己的查看记录（时间、类别、编号）。
- 被看的人（比如提交企业验证的雇主）删除账号时，记录不动：里面只有申请的编号，没有他们的邮箱或姓名，申请本身照 #78 的做法去掉姓名和邮箱。

## 后果

- 发生泄露或有人投诉时，能回答「哪位审核员、什么时候看过这条」。
- 以后给审核员看聊天、求职者资料（比如聊天举报）时，Server Function 必须先 `recordViews(…, "chat" | "profile", …)`，PR 里写明。
- 被看的人申请查阅自己的信息（IPP 6、第四十五条）时，能从这张表查到被看过几次、什么时候；导出里没有放，因为会带出审核员的邮箱。要的话手工答复，不写审核员是谁。
- 表里的数据随正式数据库一起放在悉尼，国内同事直连时也能看到这张表：它跟其他表一样受同样的访问控制。
