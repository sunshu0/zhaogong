# 0048 手机上弹出来的面板和「更多」都是底部弹层

- 状态：已采纳（导师 local_bf04d210 派的说明 `zg-scratch/mentor-bf04/brief-B-18.md`；执行 B local_ff52409b 起草）
- 日期：2026-10-27。Issue #413。用户 10-27 01:24：「操作手感就先按你的方案执行」（五件里的第四件：T6 弹窗换成底部弹层）。

## 情况

第 19 轮做了 `BottomSheet`（筛选、`Select` 在用）：手机上从底部滑上来，能拖把手关、点遮罩关。但别的弹出面板没跟上：

- 聊天和职位页的面板（分享、聊天举报、常用语、发简历、交换联系方式）用的是 `ChatDialog`：手机上也贴底、滑上来，可是没有把手、拖不动，点遮罩也不关，只能够到顶上的「关闭」，单手拿手机够不着。
- 「更多」（`MoreMenu`，聊天和雇主的职位管理在用）是挂在按钮下面的小下拉，手机上按钮在右上角，菜单也在右上角。
- 键盘起来时，Safari 不缩页面（只缩看得见的那部分），贴底的面板下半截被键盘盖住，常用语、举报说明的输入框可能看不见。

## 决定

1. **拖动和让键盘抽成两个钩子**（`src/components/ui/use-sheet.ts`）：`useSheetDrag`（原来写在 `BottomSheet` 里，规则还是 `sheet-drag.ts` 的 `shouldDismiss`：拖 80 px 或快速一甩）和 `useKeyboardRoom`（`visualViewport` 比页面矮出 80 px 以上、又不是双指放大时，面板的下边距等于被盖住的高度，高度不超过看得见的部分；规则在 `sheet-keyboard.ts`，有单元测试）。`BottomSheet` 和 `ChatDialog` 都用。Chrome 在聊天页本来就缩页面（`interactive-widget=resizes-content`），这时算出来是 0，不动。
2. **`ChatDialog` 在手机上就是底部弹层**：顶上加把手，标题那一条能往下拖；点遮罩关；标题固定、内容自己滚。拖和点遮罩只在 768 px 以下算（开始拖、点的那一刻看窗口宽），768 px 起的居中面板和以前一模一样（点旁边照旧不关，免得桌面上误点丢了填了一半的举报）。用它的几个组件一行没改。
3. **`MoreMenu` 在手机上把同一个菜单放进 `BottomSheet`**：标题是按钮的名字（「更多：某某」「更多操作：某职位」），里面还是 `role="menu"` 和同样的项、同样的键（↑↓、Home / End、Enter、Esc）。打开那一刻定用哪种（`sheetFromBottom()`），开着时转屏不换。弹层是模态的，Tab 不再关菜单，留在面板里。弹层开着时后面的页面不能拿焦点，所以选了一项以后，等弹层真正关掉（下一次 effect）再把焦点还给按钮、再执行那一项：这样那一项自己给的焦点（比如职位卡片「结束招聘」的问题）不会被弹层关闭时还焦点抢走。弹层放在按钮的外层里（DOM 上），所以 e2e 的 `card.getByRole("menuitem")` 照旧找得到；`ChatThread` 不用改（A 的 #407 正在改它）。
4. 两种面板都标 `aria-modal="true"`、`aria-labelledby` 指向标题；原生 `showModal()` 管焦点不出面板，关了焦点回到打开它的按钮。「减少动态效果」照全站规则不滑。

## 不做的

- 职位举报照旧在页内展开（表单长，弹层里不好填）。
- 下拉刷新、震动（用户 01:24 定的拆法里去掉了）。
- 键盘起来时聊天里活跃度两行、常用语一行的收拢：等 A 的 #407 合并后另派。

## 后果

- 规则写进 `docs/design-system.md`「第 19 轮：操作质感」的共用组件表和「弹出来的面板都是底部弹层（#413）」。
- 以后新的弹出面板：手机上要能单手关，就用 `BottomSheet`，或照 `ChatDialog` 接 `useSheetDrag` / `useKeyboardRoom`。
- e2e：`e2e/bottom-sheets.spec.ts`（手机：从底部出、拖关、点遮罩关、焦点回按钮、「更多」的键盘、axe 0 违规；桌面：照旧居中、照旧下拉）。
